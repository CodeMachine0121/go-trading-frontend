# 外掛授權同意頁 — Requirements Brief

## Goal

今天要讓 Claude Code 這類外掛代使用者操作交易服務，得在對話裡把電子郵件與密碼告訴它——
密碼因此出現在對話紀錄裡，而且外掛拿到的是「能以他的身分做任何事」的那一組帳密本身。
交易服務改成業界通行的**外掛授權**：外掛要取得身分時，把使用者送到操作台的一個頁面，
使用者在**操作台自己的登入畫面**登入，看清楚是哪一個外掛在要求什麼，再親手按「允許」或「拒絕」；
結果交回外掛，外掛從此自己續用，不必再問任何人要密碼。

這一刀在操作台這一側要做的是那一頁：**外掛授權同意頁**。
它要讓人看得懂自己正在把什麼交給誰、絕不替人按下允許，並且在每一種結局
（允許、拒絕、請求已失效、連不上）都清楚告訴他接下來該去哪裡。

## Requirements

- 外掛把使用者送來時會附上一張**授權請求**的識別；操作台以此找到那一次請求。
- **這一頁要先登入**。沒登入的人先被帶去登入畫面，登入之後**回到同一張授權請求**，不能變成回到第一站。
- **還沒被放行（待開通）的人只看得到等待開通那一頁**——與操作台其他每一頁一樣，這一頁不開例外。
- 頁面說清楚四件事：**提出要求的外掛名稱**、**目前登入的是哪一個帳號**、
  允許之後**這個外掛能以他的身分使用交易服務的全部功能**、以及「允許」與「拒絕」兩個選擇。
- **絕不自動允許**：只有使用者親手按下「允許」才算允許；打開頁面、重新整理都不會替他做決定。
- 按「允許」或「拒絕」之後，瀏覽器被送回外掛那一側，由外掛接手；操作台這一頁接著說
  「**可以關掉這個分頁，回到 Claude Code**」。
- 授權請求**已經過期、已經被用過、或根本不存在**時，說清楚：這一張授權請求已失效，
  **回到 Claude Code 重新連線**。不給允許與拒絕。
- 按下選擇之後、結果回來之前，兩個選擇都不能再按一次——同一張請求只能被決定一次。
- 連不上交易服務時，說明是連不上，並讓他再試一次；這不是請求失效，不能說成失效。

## Examples (Specification by Example)

### Rule: 這一頁要先登入，登入後回到同一張授權請求

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 沒登入；授權請求「甲」 | 外掛把他送到授權頁 | 先到登入畫面；登入成功後回到授權頁，看到的仍是請求「甲」 |
| 2 (happy) | 已登入、已放行；請求「甲」 | 外掛把他送到授權頁 | 直接看到同意頁 |
| 3 (exception) | 已登入但待開通 | 外掛把他送到授權頁 | 被帶到等待開通那一頁，看不到同意頁 |

### Rule: 同意頁說清楚是誰、要什麼、給誰

| # | Given | When | Then |
|---|---|---|---|
| 4 (happy) | 請求「甲」由外掛「Claude Code」提出；登入者 james@example.com | 打開授權頁 | 看到外掛名稱「Claude Code」、帳號 james@example.com、「能以你的身分使用交易服務全部功能」、允許與拒絕 |
| 5 (boundary) | 同上 | 打開頁面後什麼都不按、或重新整理 | 什麼都沒有被決定；頁面仍在等他選 |

### Rule: 允許與拒絕把結果交回外掛

| # | Given | When | Then |
|---|---|---|---|
| 6 (happy) | 同意頁上，請求「甲」有效 | 按「允許」 | 請求被允許，瀏覽器被送回外掛；頁面說可以關掉分頁回到 Claude Code |
| 7 (happy) | 同意頁上，請求「甲」有效 | 按「拒絕」 | 請求被拒絕，瀏覽器被送回外掛（外掛得知被拒）；頁面說可以關掉分頁回到 Claude Code |
| 8 (boundary) | 剛按下「允許」，結果還沒回來 | 再按一次「允許」或按「拒絕」 | 按不下去；只算第一次 |

### Rule: 失效的請求說失效，連不上的說連不上

| # | Given | When | Then |
|---|---|---|---|
| 9 (exception) | 請求「甲」已過期（超過十分鐘）或已被決定過 | 打開授權頁 | 說「這一張授權請求已失效或已被使用，請回到 Claude Code 重新連線」；沒有允許與拒絕 |
| 10 (exception) | 網址上沒有授權請求 | 打開授權頁 | 同上，說它已失效，請回到 Claude Code 重新連線 |
| 11 (boundary) | 頁面打開時請求有效，停在頁面上超過十分鐘 | 按「允許」 | 說請求已失效，請回到 Claude Code 重新連線；沒有被送回外掛 |
| 12 (exception) | 交易服務沒開 | 打開授權頁 | 說連不上交易服務，給「再試一次」；不說成失效 |
| 13 (exception) | 同意頁上，按「允許」時交易服務沒回應 | 按「允許」 | 說連不上，兩個選擇恢復可按，可以再試 |

## Out of Scope

- 交易服務那一側的授權流程本身、外掛那一側的連線與續用（另兩個切片）。
- 在同意頁上「換一個帳號」：要換帳號就先登出再從 Claude Code 重新連線。
- 管理已經授權過的外掛（列出、撤銷）。
- 限定外掛只能用部分功能：這一版一律是全部功能。
- 登入在同意頁上途中完全失效（連續用也救不回來）時記住這張請求：照操作台既有做法回到登入畫面，
  請求十分鐘內就失效，重新從 Claude Code 連線即可。
- 待開通的人在開通之後自動回到這張請求：開通通常不在十分鐘內完成，請求早已失效。

## Context / Background

決定（以共識契約與業界慣例代替提問）：

- 頁面不套用操作台外框，與登入頁、等待開通頁同一類「還沒進到操作台裡」的卡片版面——
  使用者是從外掛被送過來的，這一頁唯一的事就是做決定。
- 允許與拒絕的份量不同：允許是主要動作，拒絕是次要動作；兩者並排，拒絕不藏起來。
- 被送回外掛之後仍留一個畫面說「可以關掉這個分頁」，因為外掛那一側的畫面有時什麼都不顯示，
  使用者需要知道事情已經做完。
- 失效的請求一律同一句話，不區分過期、用過或不存在——對使用者的下一步都一樣：回 Claude Code 重新連線。
- 登入之後回到原本那一張請求：操作台既有的門本來就會記下完整的目的地（含授權請求的識別），
  這一刀要把它釘住，不讓它在日後的改動中悄悄只記路徑。
