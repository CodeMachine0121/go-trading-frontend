**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering, QA

## 1. Background & Goal

### Problem Statement

後端的回測**只做現貨了**——借錢、做空與強制平倉整組移出，
因為它們描述的是合約帳戶上的事，而那是另外一件事。

畫面上還擺著三樣**送出去必定被拒絕**的東西：回測表單與工作台上的交易模式四選一、
回測表單上的槓桿與維持保證金率、機器人建議部位上的槓桿。
成績單上還留著一格「強平出場」，等一個永遠不來的數字。

**這種過期最難發現的地方是：它不像壞掉。** 那幾格畫得好好的、填得下去、
有說明文字、有驗證訊息。使用者挑「槓桿做多」、填五倍、按下重演，
收到一句他看不懂的拒絕——他會以為是自己填錯了，回頭改數字，再試一次。

### Expected Outcome

- **那三樣東西看不到，也就填不了**——不是填了才被擋。
- **成績單不再有強平那一格。**
- **畫面說得出這裡只做現貨**，而不是讓一組選項默默消失。
- **既有的機器人與交易策略照舊打得開、改得動、存得回去。**
- 其餘每一格逐字不變。

### Out of Scope

- **合約的回測畫面。** 後端那邊是另外一刀。
- 止損、止盈、交易成本、每次開倉押多少——完整保留。
- 任何一個頁面的路由與導覽。
- 成績單其他每一格的算法與排版。

## 2. User Personas

- **Primary Role:** 這個工作台唯一的使用者。他手上跑的四份交易策略全是現貨、
  五台機器人的槓桿全是一倍——這一刀拿掉的是他從來沒用過的那幾格。
- **Usage Context:** 桌機上調策略、跑回測、讀成績單；手機上讀機器人訊息。

## 3. User Stories & Acceptance Criteria

### US-01 — 表單上沒有填不得的格子 [priority: P0]

**As a** 這個工作台的使用者，
**I want** 回測表單上不再有交易模式、槓桿與維持保證金率，
**so that** 我不會填一組送出去必定被拒絕的值，然後以為是自己填錯了。

```gherkin
Scenario: 策略腳本回測面板沒有那三格
  Given 策略腳本回測面板
  When 看那張表單
  Then 看得到起訖、初始資金、每次開倉押多少、止損、止盈與兩個成本率
  And 沒有交易模式那一組,也沒有槓桿與維持保證金率

Scenario: 交易策略回測面板沒有那三格
  Given 交易策略回測面板
  When 看那張表單
  Then 沒有交易模式那一組,也沒有槓桿與維持保證金率

Scenario: 交易策略工作台不再問交易模式
  Given 交易策略工作台的表單
  When 看那張表單
  Then 看得到名稱、信號來源、買入條件與賣出條件
  And 沒有交易模式那一組

Scenario: 機器人的建議部位剩四格
  Given 機器人表單,建議部位那一段
  When 看那幾格
  Then 看得到部位資金、每次開倉押多少、停損距離、停利距離
  And 沒有槓桿那一格
```

### US-02 — 成績單只報它真的算得出來的 [priority: P0]

**As a** 讀成績單的人，
**I want** 上面不再有「強平出場」，
**so that** 我不會在一張現貨的成績單上找一個只有合約帳戶才有的數字。

```gherkin
Scenario: 成績單沒有強平那一格
  Given 一次跑完的回測
  When 看成績單
  Then 找不到「強平出場」

Scenario: 還在的那幾格照舊
  Given 同一張成績單
  When 看止損出場與止盈出場
  Then 兩格都在,數字與這一刀之前逐格相同
  And 累計成本那一格也在
```

### US-03 — 畫面說得出這裡只做現貨 [priority: P0]

**As a** 上一次來還看得到四個選項的使用者，
**I want** 那個位置留一句話告訴我現在只做現貨，
**so that** 我不會以為是畫面壞了,或是自己記錯了。

```gherkin
Scenario: 原本那一組的位置留著一句話
  Given 回測表單
  When 看交易模式原本那一組的位置
  Then 那裡有一句話,說這裡的重演只做現貨

Scenario: 那句話說得出倉位怎麼走
  Given 那句話
  When 讀它
  Then 它說出買入時空手就開倉、賣出就平倉把錢收回來、空手時聽到賣出什麼都不做

Scenario: 那句話說得出這裡做不到什麼
  Given 那句話
  When 讀它
  Then 它說出借錢與做空是合約帳戶的事,這裡不做
```

### US-04 — 既有的東西照舊打得開 [priority: P0]

**As a** 手上有四份交易策略與五台機器人的人，
**I want** 這一刀不要讓它們失效，
**so that** 我不必為了一個我從來沒用過的欄位去重建它們。

```gherkin
Scenario: 既有的交易策略打得開也存得回去
  Given 一份這一刀之前存下的交易策略
  When 打開它來改,改個名字就存
  Then 存得起來,信號來源與兩個條件逐項不變

Scenario: 既有的機器人打得開也存得回去
  Given 一台這一刀之前建立的機器人,建議部位當初存著一倍槓桿
  When 打開它來改,改個觸發間隔就存
  Then 存得起來,建議部位的其餘四格逐項不變
  And 送出去的內容裡沒有槓桿
```

### US-05 — 其餘一格都不動 [priority: P0]

**As a** 使用者，
**I want** 這一刀只碰回測這件事，
**so that** 我正在用的 K 線圖、策略腳本與機器人的其他設定不會被波及。

```gherkin
Scenario: 保留的那幾格逐字不變
  Given 止損、止盈與兩個成本率那幾格
  When 這一刀做完之後看它們
  Then 位置、標籤、驗證訊息與說明逐字相同

Scenario: 無關的畫面逐字不變
  Given K 線圖、策略腳本編輯、機器人的其他設定
  When 這一刀做完之後看它們
  Then 與這一刀之前逐字相同
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 從畫面上消失的四樣**

| 畫面 | 消失的 |
| :--- | :--- |
| 策略腳本回測面板 · 交易策略回測面板 | 交易模式那一組、槓桿、維持保證金率 |
| 交易策略工作台 | 交易模式那一組 |
| 機器人表單 | 建議部位裡的槓桿 |
| 成績單 | 強平出場 |

**消失＝看不到，也就填不了、送不出。**

**R2 — 原本那一組的位置留一句話**

那句話要說三件事：這裡只做現貨、倉位怎麼走、借錢與做空是另一件事。
**不是默默把整組拿掉**——一組選項無故消失，使用者會以為畫面壞了。

**R3 — 既有資料讀得進、改得動**

一台存著一倍槓桿的機器人：**讀進來、不顯示、不送出**。
一倍本來就是「沒有槓桿」，不影響任何數字；而畫面上留一格只能填一的欄位，
是一個等著被填錯的空格。
一份存著 `spot` 的交易策略：那個欄位不再被讀，也不再被送出。

**R4 — 送出去的內容裡不再有那三個欄位**

這是 R1 的機械面：畫面上沒有不等於送出去沒有。
表單模型、DTO 與 proxy 都要跟著拿掉，否則欄位會以預設值被送出去，
而後端會整份拒絕——使用者看到一句與他剛做的事對不起來的話。

### Edge Cases

- **後端仍回傳 `liquidationExitCount`**：不會（上游已移除），
  但即使回傳了，成績單也不再讀它。
- **後端仍回傳 `tradingMode`**：不會，且畫面不再讀它。
- **既有機器人存著大於一的槓桿**：實務上不存在（五台全是一倍）；
  若有，它會被讀進來、不顯示、不送出——而下一次存檔就把它清掉了。

## 5. UI/UX Design & Interaction

- **原型：** 無新的視覺設計。這一刀移除既有元素，並在其中一處留一句說明文字。
- **關鍵互動：**
  - 交易模式那一組（單選鈕）→ 換成一段說明文字，**位置與標題不變**。
  - 槓桿那一組（兩個輸入框 + 一則錯誤訊息）→ 整組移除。
  - 成績單的強平那一格（原本 `v-if="liquidationExitCount > 0"`）→ 整格移除。
  - 機器人建議部位的槓桿輸入框 → 整格移除，其餘四格的排版與間距不變。
- **空狀態／載入／錯誤：** 皆不受影響。

---

## 6. Non-Functional Requirements

- **相容性：** 既有的交易策略與機器人打得開、改得動、存得回去。不需要任何資料遷移。
- **一致性：** 畫面問的每一件事，後端都真的收得下——這是這一刀唯一的驗收標準。
- **樣式：** 移除元素後不得留下孤兒樣式規則或未使用的 token。

## 7. Dependencies & Risks

### Dependencies

- **後端的 `2026-09-22-spot-only-backtest`。** 這個畫面描述的是那一刀之後的服務。

### Known Risks

| 風險 | 說明 | 處置 |
| :--- | :--- | :--- |
| **刪漏一半** | 畫面拿掉了，表單模型或 proxy 還在送 | R4：三層一起拿掉，並以「送出去的內容裡沒有它」為斷言 |
| **孤兒樣式** | 元素移除了，`.backtest-condition-fields__leverage` 之類的規則留著 | 樣式檢查（`lint:style`）與人工複查一起把關 |
