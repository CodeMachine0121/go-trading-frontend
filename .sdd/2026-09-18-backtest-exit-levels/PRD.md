**範圍**：`go-trading-frontend`
**狀態**：Finalized
**來源共識**：[BRIEF.md](BRIEF.md)

## 1. Background & Goal

### Problem Statement

後端的回測現在可以模擬止損與止盈（`go-trading#45`）：
發動重演時多說兩個距離（各自選填的百分點），成績單裡的最終權益、
總報酬率、勝率、最大回落**全部反映那些出場**。

畫面上沒有那兩格。

而這件事在畫面上比在任何其他地方更要緊：**畫面就是使用者真正在調策略的地方**。
他不會為了試一個 2% 的停損去開一個 MCP 連接器。他會打開回測那一頁、
改一個數字、按執行、看數字怎麼變——一圈一圈來。
那兩格不在，他那一圈裡就少了**最重要的一個旋鈕**。

同一支腳本、同一段歷史：不設停損 **+25%**，停損放 2% **−2%**。
他看得到的只有前者，而他打算掛的是後者。

### Expected Outcome

- 回測條件區多一組「出場價位」：止損距離、止盈距離，皆選填，**兩個回測畫面都有**。
- 留白就不模擬，而那一格旁邊**說得出**這件事。
- 不合法**當場不送出**，句子與後端逐字相同，訊息標在那一組旁邊。
- 成績單多兩格出場筆數；交易明細每一列標出出場原因。

### Out of Scope

| 不做 | 為什麼 |
|:---|:---|
| 一次看兩張成績單比較有無停損 | 一次一種，跑兩次——與交易模式同一個理由 |
| 記住上次填的距離 | 它跟著這一次走，與初始資金、押多少同一類 |
| 從機器人那組帶過來 | 同名、不同事：那組從最新價量，這組從進場價量 |
| 移動停損／手續費／滑點 | 後端沒有，畫面不發明 |

## 2. User Personas

| Persona | 他在這一刀要什麼 |
|:---|:---|
| **策略調校者（唯一使用者）** | 他正打算給機器人配一個停損。他要在掛上去**之前**知道那個停損在過去會讓他賺還是賠——而他做這件事的地方就是這一頁 |

**Usage Context:** 他會**連續跑兩次**：一次留白、一次填 2%，然後把兩張成績單擺在一起。
這一組欄位存在的樣子就是那兩次之間**只改一個數字**。

## 3. User Stories & Acceptance Criteria

### US-01 — 回測條件區填得出那兩個距離 [priority: P0]

**As a** 策略調校者，**I want** 在回測條件裡填止損與止盈距離，
**so that** 我看到的成績單算的是我真正打算跑的那個策略。

```gherkin
Scenario: 兩格都填
  When  填止損 2、止盈 5 並按執行
  Then  兩個值都送到後端

Scenario: 兩格都留白
  When  兩格都不填就按執行
  Then  請求裡不出現那兩個值
  And   成績單與這一刀之前一字不差

Scenario: 只填一格
  When  只填止損
  Then  只有止損被送出去
```

**Acceptance Criteria**

- **AC-01** 「出場價位」一組兩格，**皆選填**，預設留白。
- **AC-02** **兩個回測畫面都有**（腳本回測、交易策略回測），且兩邊都是**填得動的輸入框**——
  與交易模式不同（那一邊在交易策略回測上是一句話）。
- **AC-03** 留白時**請求不帶那兩個值**（不送零、不送空字串）。
- **AC-04** 那一組旁邊**說得出「留白就不模擬」**。
  這是最容易猜錯的一條，而猜錯的後果是他以為自己已經對過帳了。
- **AC-05** 距離**不隨任何其他欄位切換而清掉**——與押注數字同一條規則。

---

### US-02 — 不合法當場不送出，而且只有一份說法 [priority: P0]

**As a** 策略調校者，**I want** 填錯時當場被擋住並看到原因，
**so that** 我不必送一次出去才知道。

**Acceptance Criteria**

- **AC-06** 距離為負 → **不送出**，訊息「停損距離不得為負」／「停利距離不得為負」。
- **AC-07** 距離超過 100 → **不送出**，訊息說出「會讓價格變成負數」。
- **AC-08** 正好 100 → **送得出去**。
- **AC-09** 訊息**標在「出場價位」這一組旁邊**（欄位名 `exitLevels`）。
- **AC-10** **句子與後端逐字相同**，且**與機器人表單上那兩格逐字相同**。
- **AC-11** 那兩句話在這個專案裡**只有一份**。
  目前它是機器人部位規劃模型的一個**私有方法**——那時只有一個呼叫者，
  所以沒問題；現在有了第二個，它要搬到兩邊都看得到的地方。
- **AC-12** 一次只說一個理由（沿用這張表單既有的每一條）。
- **AC-13** 後端指名 `exitLevels` 時，訊息落在同一組旁邊
  （認不得的欄位名仍然變成籠統的拒絕，未改動）。

---

### US-03 — 成績單說得出出場是怎麼發生的 [priority: P0]

**As a** 策略調校者，**I want** 看到有幾筆是被停損掃出去的，
**so that** 我分得出「靠訊號賺到的 +8%」與「一路被停損削到只剩 +8%」。

**Acceptance Criteria**

- **AC-14** 成績單多兩格：**止損出場**、**止盈出場**。
- **AC-15** 那兩格**大於零才出現**，與「規則打架的棒數」同一條規則。
- **AC-16** 交易明細多一欄**出場原因**：訊號／止損／止盈。
- **AC-17** 沒有模擬出場的那一次，每一列都是**訊號**。
- **AC-18** 中文說法在 domain 決定，畫面只負責畫——與方向標籤、賺賠色調同一條規則。

> **AC-15 為什麼不是「沒填距離時才隱藏」**：後端不會回「這一次有沒有模擬」，
> 只會回筆數。而「我設了停損但它一次都沒被碰到」這件事，
> **交易明細那一欄已經說出來了**（每一列都寫著訊號）。
> 為了那個情境多送一個旗標回來，是為了一格顯示而加一份狀態。

## 4. Business Flow & Logic

```
回測條件區（兩個畫面共用的那個分子）
  · 止損距離 %   ← 這一刀新增
  · 止盈距離 %   ← 這一刀新增
        │  文字
        ▼
  BacktestRequestDto / TradingStrategyBacktestRequestDto（各多兩個精確小數）
        │
        ▼
  對應的 Request Domain Model ── 建構當下驗證 ──┐
        │                                        └─ 不合法 → BacktestFieldError('exitLevels', 句子)
        ▼                                                     └─ 那句話來自兩張表單共用的那一份
  Proxy ── 大於零才放進 body ──▶ 後端
        │
        ▼
  回應（成績單多兩個筆數、每一筆多一個原因）
        │
        ▼
  Backtest entity ──▶ BacktestDomain ──▶ DTO（中文說法、進位、色調全在這裡決定）
        │
        ▼
  成績單卡（多兩格，大於零才出現）／交易明細（多一欄）
```

### Core Business Rules

| # | 規則 | 為什麼 |
|:--|:---|:---|
| BR-01 | 留白不送出那兩個值 | 「留白＝不模擬」是後端的規則；送個零雖然等價，但**空字串轉成的零是巧合而不是意圖**，而下一次後端改讀法時那個巧合會壞掉 |
| BR-02 | 那兩句拒絕的話**一份** | 兩張表單問同一件事。多一份的那一天，同一個 150 會有兩種說法 |
| BR-03 | 一個欄位名蓋兩格 | 併排的一組，句子已說出是哪一格。後端也是這樣回的 |
| BR-04 | 兩格大於零才出現 | 與打架棒數同一條規則。永遠是零的格子讓人以為它有意思 |
| BR-05 | 出場原因的中文在 domain | 與方向標籤同一條規則：畫面一開始判斷，同一個判斷就會散到每個顯示它的地方 |
| BR-06 | 距離不隨模式切換清掉 | 與押注數字同一條規則：他本來就沒有改過它 |

### Edge Cases

| 情境 | 行為 |
|:---|:---|
| 填了非數字（輸入框是 number，但可以清空） | 空 → 視為不模擬；`NaN` → 擋住並說「請填一個數字」（沿用既有那一句） |
| 兩格都填了但整段從沒觸發 | 兩個筆數都是 0 → 那兩格不出現；明細每一列都是「訊號」 |
| 後端回了一個畫面認不得的欄位名 | 沿用既有行為：變成一則籠統的拒絕（未改動） |
| 交易策略回測畫面 | 那兩格照樣填得動——這一刀不在那一邊畫成一句話 |

## 5. UI/UX Design & Interaction

| 位置 | 改動 |
|:---|:---|
| 回測條件區 | 新增兩格輸入框：「止損距離（%）」、「止盈距離（%）」，皆選填、預設留白 |
| 那一組旁邊 | 一句說明：**留白就不模擬；距離從進場價量起** |
| 拒絕訊息 | 標在那一組旁邊 |
| 成績單卡 | 多兩格：止損出場、止盈出場（大於零才出現） |
| 交易明細 | 多一欄出場原因，擺在出場價之後、賺賠之前——它說的是**那一次出場**的事 |

**兩格擺在一起佔滿整列**，與交易模式那一格同一個理由：
它們是**一組**，而一句「留白就不模擬」被折成一疊時就沒有人會讀它。

## 6. Non-Functional Requirements

| 面向 | 要求 |
|:---|:---|
| **相容性** | 兩格留白時，送出去的 body 與這一刀之前**逐字相同**；既有測試斷言**不改** |
| 一致性 | 精確小數一律 `decimal.js`；**零的判斷一律 `greaterThan(0)`**，不用 `isPositive()`——`decimal.js` 把零當成正的，而後端不是 |
| 分層 | 元件只看得到 DTO 與哨兵錯誤（eslint 擋著） |
| 可測性 | 兩個新模型皆 table-driven；元件測到「有沒有那一格、訊息在不在那一組旁邊」 |

## 7. Dependencies & Risks

| 項目 | 說明 | 處置 |
|:---|:---|:---|
| **依賴** 後端已支援 | 兩個端點都要收那兩個欄位、都要回那三個新欄位 | `go-trading#45` 已交付 |
| **風險** `decimal.js` 把零當成正的 | `new Decimal(0).isPositive() === true`，而 Go 的不是。上一刀在這裡踩過一次：空的資金被前端讀成「有一組規劃」而後端讀成「沒有」 | **一律用 `greaterThan(0)`**，並在程式碼裡寫明理由 |
| **風險** 兩句拒絕的話分岔 | 兩張表單問同一件事 | AC-11：搬成一份共用的模型 |
| **風險** number 輸入框的 `v-model` 回傳數字 | 上一刀踩過：`text.trim()` 在第一次按鍵就炸 | 沿用上一刀的 `String(text).trim()` 手法 |
| **風險** 成績單既有數字位移 | 最不可接受的結果 | 留白＝不送＝後端不模擬；既有測試不改 |

## 8. Appendix

### 新增／搬家的模型

| 模型 | 為什麼 |
|:---|:---|
| `ExitDistanceDomain`（新） | 一個出場距離講不講得通。**兩張表單共用**——這是這一刀唯一的重構 |
| `BacktestExitLevelsDomain`（新） | 這一次重演的那兩個距離，驗證並把拒絕說成這張表單聽得懂的話 |
| `PositionPlanDomain`（改） | 它的私有 `distanceRejection` **委派**出去，與它已經在委派押多少的手法一字不差 |

### 詞彙

沿用後端 UL-MAP 的：出場價位、回測止損距離、回測止盈距離、出場原因、
止損出場筆數、止盈出場筆數。**畫面不自創同義詞。**

出場原因的中文說法：**訊號／止損／止盈**（在 domain 決定，與方向的做多／做空同一個位置）。
