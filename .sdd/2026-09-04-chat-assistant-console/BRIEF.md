# 行情對話助手上操作台 — Requirements Brief

## Goal

操作台現在有四個地方可去：看連線狀態、翻 K 線、看圖、算指標。每一個都要求使用者
**先知道自己該去哪一個、該填哪幾格**。想問「BTCUSDT 最近一天怎麼走」，得先決定
去圖表頁還是瀏覽頁、要多粗的 K 線、要看多長一段。

後端已經有一位**助手**能替人做這件翻譯：問一句日常的話，它自己去取數，再用一段話講回來。
但目前只有 Postman 叫得動它——也就是說，這個操作台裡最不需要「先懂介面」的功能，
反而是唯一沒有介面的。

這個切片把助手搬上畫面。而且是**兩個地方**：

- **一整頁**，左邊是每一段對話、右邊是對話串。要專心問一串問題時去那裡。
- **一個抽屜**，任何畫面都叫得出來。看著圖想問一句時，不必離開那張圖。

兩個地方**接的是同一段對話**——在抽屜問的，展開到整頁還在。

## Requirements

**助手住在兩個地方**

- 左側導覽多一個目的地，通往**助手整頁**：左邊對話清單、右邊對話串與輸入框。
- 每一個畫面都能叫出**助手抽屜**：右側滑出，單欄的對話串與輸入框，畫面其餘部分照樣看得到。
- 抽屜**不放對話清單**——它太窄，放進去只會兩邊都難用。抽屜標頭給一個**展開**，
  帶著目前這段對話跳到整頁。
- **兩邊共用「目前這段對話」。** 抽屜關掉再打開、在畫面之間走動，回來時仍是同一段。
- 換到別的畫面時抽屜收起來。它是隨手問一句的地方，不是常駐的側欄。

**問一句，得一句**

- 輸入框打一句話送出。對話串**先長出這句提問**，接著才出現回答。
- 沒有指名對話時，這一句就開一段新的；之後的每一句都追加在同一段後面。
- 提問**空白時送不出去**——送出鍵是暗的，不打擾後端。前後空白不予保留。
- 輸入框隨著內容長高，到一個高度上限後在裡面捲動。

**等待那最長兩分鐘**

助手一次回答可能要來回查好幾次，因此**比操作台任何既有操作都久**。

- 送出後，提問下面出現「助手正在查…」的佔位；**輸入框與送出鍵鎖住**。
- 回答回來，佔位換成回答，輸入框解鎖並自動聚焦，好接著問下一句。
- 等待中**不能送出第二句**。
- 等待中切到別的畫面再切回來，那一次問答**不會消失、也不會重送**。

**回答的結構要看得出來**

助手講帶數字的事情時會用小標與條列。整段擠成一團的話，數字就藏在裡面了。

- 小標呈現為小標、條列呈現為條列、強調的字比周圍重、代號那類短字串以等寬字呈現。
- 就是一段白話時**不硬加結構**。
- 助手若排了一個表格，那幾行**照原樣當文字呈現**——這個切片不畫表格。
- 回答裡任何看起來像網頁標籤的字，一律**原樣當文字顯示**，不會被當成指令執行。

**剛收到那一則，附一行低調的說明**

- 該則下方一行：這次**查了幾次**、**動用多少份量**。一次都沒查時只講份量。
- 助手若因為**達到查詢次數上限**而提早收尾，該則另外標明
  「已達查詢次數上限，這是就目前所得的回答」——語氣是提醒，不是錯誤。
  半個誠實的答案比沒有答案有用，但使用者得知道它是半個。
- **重新載入畫面之後這行附註就不見了。** 那組數字屬於剛才那一次往返，
  事後回頭看拿不到，也沒有必要為此把它留下來。

**四種拒絕，四種說法**

拒絕的意義不同，使用者要做的事就不同，因此不可以混成一種說法。

| 發生什麼 | 使用者要做什麼 | 怎麼呈現 |
| :--- | :--- | :--- |
| 今日額度用盡 | 等 | 回答的位置出現警示塊：額度已用盡、何時重置 |
| 助手沒回應或逾時 | 稍後再試 | 同一位置的警示塊：助手目前沒回應 |
| 指名的對話不存在 | 開一段新的 | 明說找不到這段對話，並退回新對話 |
| 連不上後端 | 去把後端啟動 | 沿用操作台既有的說法——這不是助手的問題 |

- 警示塊出現時，**提問留在輸入框裡不清空**，並附一個**再試一次**：重送剛才那一句，不必重打。
- 警示塊長在**回答該出現的位置**，不是畫面頂端的橫幅。它屬於那一次問答，不屬於整個畫面。

**回頭找對話**

- 對話清單依**最近有動靜**由新到舊排列，每一段顯示最後有動靜的時刻與有幾則訊息。
- 正在看的那一段在清單上標出來。
- 挑另一段就在右邊換成那一段的每一則訊息，由早到晚。
- **開新對話**清空對話串回到建議提問；舊那段仍留在清單上。
- 一段對話都沒有時**明說「還沒有任何對話」並直接給建議提問**，不留一片白。
- 所有時刻照使用者選的顯示時區呈現。

**建議提問**

助手辦得到的事有好幾種，但使用者從畫面上**看不出來**。空的對話因此不能只放一句
「請開始輸入」——那等於要人猜。

- 空的對話出現幾句可直接點的範例提問，涵蓋助手辦得到的幾種事。
- 點一下**直接送出**，不必再按送出鍵。
- 對話已經有訊息時，建議提問收起來，不再佔位置。

## Out of Scope

- **逐字浮現的回答**——後端一問一答，講完才回，畫面照這樣呈現。
- **刪除或替對話命名**——後端沒有這兩件事。
- **把表格畫成表格**、圖片、附件。
- **顯示助手每一次查了什麼**——後端讀一段對話時不回這些，本切片不為此改後端。
- **今日額度還剩多少的儀表**——後端只在額度用盡時才說得出這件事。
- **改變任何既有畫面的行為**——K 線瀏覽、圖表、指標計算一律照原樣，只多一顆叫出抽屜的鍵。

## Open Decisions

Items the PRD author should resolve:

- 建議提問**具體是哪幾句**，以及要涵蓋助手辦得到的哪幾種事。
- 輸入框長高的**高度上限**。
- 抽屜的**寬度**，以及它與整頁的分界（多窄以下不放清單）。
- 「助手正在查…」等超過多久要多說一句安慰的話（或完全不必）。
- 附註那一行**份量**要用什麼說法呈現給人看（原始數字、或換算成別的說法）。

## Context / Background

釘板的幾件事：

- **兩個地方都做，但不重複做兩套。** 抽屜與整頁是同一段對話的兩種密度：
  一個為了「看著圖順手問」，一個為了「專心問一串」。
- **抽屜不放清單**是刻意的。窄欄硬塞兩欄的結果是兩邊都難用；換對話是低頻動作，展開再換。
- **回答要有結構**這一條是查過設計慣例才改的。原本打算純文字，
  但帶數字的助手回答幾乎都靠小標與條列在組織，純文字會讓數字沉在一面牆裡。
  代價是要把回答拆解一次——這件事由系統自己做，不引外部套件，也因此
  回答裡任何像指令的字都不可能被執行。
- **附註只出現在剛收到那一則**，因為那組數字只在那一刻拿得到。與其為了對稱而全部不顯示，
  不如在拿得到的時候誠實顯示，並接受重新載入後它會消失。
- **警示塊長在對話串裡**而不是畫面頂端。額度用盡是「這一句沒送成」，不是「整個畫面壞了」。
