# Product Requirements Document (PRD) — 現貨交易日誌（操作台）

**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** 交易服務（`go-trading` 同名切片）、外掛（`go-trading-mcp` 同名切片）、操作台

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 操作台已經有合約交易日誌，但使用者同時也在交易加密貨幣現貨與台股，這些交易在操作台上沒有地方記。
  現貨與合約是兩種東西——現貨只有先買後賣、沒有槓桿、沒有資金費用與強平——所以要**另一本日誌**。
  同時，合約日誌裡「成交」「成交價」的說法不符合合約的習慣，要改成開倉、加倉、減倉、平倉。
- **Expected Outcome:**
  - 交易日誌變成**現貨與合約兩邊都有**：在日誌頁切換頂列的現貨／合約開關就換到另一本；「交易日誌目前只有合約」的說明移除。
  - 現貨日誌沿用合約日誌已定案的版面（列表、記一筆、交易詳情、績效統計、實盤 vs 回測），拿掉合約才有的東西（方向、槓桿、資金費用、強平價、手續費率自動帶出），加上現貨才有的東西（市場、幣別、報酬率、依市場分兩組統計、台股整數股）。
  - 從現貨機器人的記到交易日誌連結打開時，依那一輪是買入或出場預填對應的表單；不按儲存就什麼都不建立。
  - 合約日誌畫面上的每一筆改叫開倉、加倉、減倉、平倉，價格叫開倉價／平倉價，均價叫開倉均價／平倉均價；合約日誌畫面**不再出現「成交」「成交價」**。
- **Out of Scope:**
  - 現貨手續費率設定（現貨手續費每筆自己填）。
  - 幣別換算、現貨與合約合併成一份統計。
  - 業務規則與計算方式本身——一律以 `go-trading` 同名切片的 PRD 為準。

---

## 2. User Personas

- **Primary Role(s):** 操作台的使用者（交易紀錄的擁有者），同時交易台股、加密貨幣現貨與永續合約。
- **Usage Context:** 下單後幾分鐘內在手機或電腦上記一筆（常從機器人訊息的連結打開）；平倉後或週末集中寫檢討、看統計。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 在兩本日誌之間切換 [P0]
**As a** 使用者, **I want** 交易日誌依現貨／合約開關切換兩本, **so that** 現貨與合約的紀錄不混在一起。

```gherkin
Scenario: 從合約日誌切到現貨日誌
  Given 使用者在合約交易日誌
  When 使用者把頂列開關切到現貨
  Then 打開現貨交易日誌，標題為「現貨交易日誌」

Scenario: 側欄依目前那一邊打開對應的日誌
  Given 使用者最後切到現貨那一邊
  When 使用者點側欄的交易日誌
  Then 打開現貨交易日誌

Scenario: 不再說日誌只有合約
  Given 使用者在任一本交易日誌
  When 使用者看頂列開關
  Then 開關可以按，且不出現「交易日誌目前只有合約」
```

### US-02 — 記一筆現貨交易 [P0]
**As a** 使用者, **I want** 記下剛買進的台股或加密現貨, **so that** 系統開始替我追蹤它。

```gherkin
Scenario: 記一筆台股
  Given 2330 是認得的台股標的
  When 使用者記一筆：2330、買進 1,000 股 @ 1,050，並儲存
  Then 建立一筆持有中的現貨交易，詳情顯示市場「台股」、以新台幣計

Scenario: 記一筆加密現貨
  Given BTCUSDT 是認得的加密貨幣現貨標的
  When 使用者記一筆：BTCUSDT、買進 0.05 @ 97,900，並儲存
  Then 建立成功，詳情顯示市場「加密貨幣」、以 USDT 計

Scenario: 表單沒有方向與槓桿
  When 使用者打開現貨的記一筆
  Then 表單沒有方向與槓桿欄位，每一筆只有買進或賣出

Scenario: 台股數量必須是整數
  Given 選的是台股標的
  When 使用者輸入買進 1,000.5 股並儲存
  Then 數量欄旁顯示「台股數量以股計，必須是整數」，表單內容保留

Scenario: 手續費留白即 0
  When 使用者記一筆買進、手續費留白並儲存
  Then 詳情上那一筆的手續費顯示 0

Scenario: 手續費自己填，含證交稅
  When 使用者記一筆台股賣出、手續費填 1,983
  Then 那一筆的手續費顯示 1,983，畫面提示台股的證交稅要併入手續費

Scenario: 已有持有中不能再新增
  Given 已有 2330 持有中的 #5
  When 使用者再記一筆 2330 並儲存
  Then 顯示交易服務的拒絕，並提供「前往 #5 加一筆買進」
```

### US-03 — 分批買賣與結果 [P0]
**As a** 使用者, **I want** 分批買進賣出並看到報酬率, **so that** 日誌和我實際的持有一致。

```gherkin
Scenario: 部分賣出
  Given 持有 1,000 股
  When 使用者加一筆賣出 400 股
  Then 狀態仍為持有中，持有顯示 600 股

Scenario: 全部賣出即平倉
  Given 持有 600 股
  When 使用者加一筆賣出 600 股
  Then 狀態變成已平倉，並提示可以去寫檢討

Scenario: 賣出超過持有
  Given 持有 600 股
  When 使用者加一筆賣出 800 股
  Then 顯示「賣出超過持有」，表單內容保留

Scenario: 平倉後的結果
  Given 買進均價 1,050、1,000 股；賣出均價 1,120；手續費合計 2,100；計畫止損 1,000
  When 使用者打開交易詳情
  Then 結果卡顯示淨損益 +67,900、報酬率 +6.47%、R +1.36

Scenario: 沒有計畫止損
  Given 一筆已平倉、沒有計畫止損的現貨交易
  When 使用者打開交易詳情
  Then 報酬率照常顯示，R 顯示「未設止損，算不出」

Scenario: 現貨沒有資金費用與強平價
  Given 一筆持有中的現貨交易
  When 使用者打開交易詳情
  Then 結果卡顯示以最新價估算的浮動損益，且沒有資金費用與預估強平價兩項

Scenario: 最大不利與最大有利
  Given 持有期間最低 1,020、最高 1,150
  When 使用者打開交易詳情
  Then 顯示最大不利與最大有利；沒有行情時寫「沒有行情資料，無法計算」

Scenario: 止損放錯邊
  Given 第一筆買進 1,050
  When 使用者把計畫止損設為 1,080 並儲存
  Then 止損欄旁顯示「止損必須低於買進價」

Scenario: 平倉後計畫鎖定
  Given 一筆已平倉的現貨交易
  When 使用者打開交易詳情
  Then 進場計畫標示已鎖定、沒有修改入口，可以加附註
```

### US-04 — 現貨統計 [P1]
**As a** 使用者, **I want** 依市場分開看現貨成績, **so that** 新台幣與 USDT 的金額不被混在一起加總。

```gherkin
Scenario: 依市場分兩組
  Given 期間內台股平倉 10 筆、加密現貨平倉 6 筆
  When 使用者打開現貨統計
  Then 台股與加密貨幣兩組分開呈現各自的勝率、平均報酬率、獲利因子、累積損益，金額不合計

Scenario: 平均 R 標示以幾筆計
  Given 台股 10 筆中 3 筆有計畫止損
  When 使用者打開現貨統計
  Then 台股的平均 R 標示「以 3 筆計」

Scenario: 失誤成本只算這一本
  Given 一筆現貨交易貼了「追價進場」
  When 使用者打開現貨統計
  Then 失誤成本出現「追價進場」；合約統計不受影響

Scenario: 期間內沒有平倉
  Given 某一組期間內沒有平倉的現貨交易
  When 使用者打開現貨統計
  Then 那一組顯示「這段期間沒有已平倉交易」，勝率為不適用
```

### US-05 — 從現貨機器人的連結打開 [P1]
**As a** 使用者, **I want** 點現貨機器人訊息的連結就打開預填好的表單, **so that** 下單後很快就能記好。

```gherkin
Scenario: 買入連結預填新增
  Given 現貨機器人買入 2330：參考價 1,050、建議數量 100 股、止損 1,000、止盈 1,150
  When 使用者點連結
  Then 打開現貨的記一筆，預填 2330、買進價 1,050、數量 100 股、止損、止盈、關聯策略
  And 買進價與數量標示「請改成實際成交」

Scenario: 沒有建議部位
  Given 現貨機器人買入，沒有建議部位
  When 使用者點連結
  Then 預填標的與買進價，數量留空

Scenario: 買入但已有持有中
  Given 已有 2330 持有中的 #5
  When 使用者點買入連結
  Then 打開 #5 的「加一筆買進」，預填參考價與數量

Scenario: 出場連結預填賣出
  Given 已有 2330 持有中 600 股的 #5
  When 使用者點出場連結
  Then 打開 #5 的「加一筆賣出」，預填賣出價＝參考價、數量 600 股

Scenario: 出場但沒有持有中
  Given 沒有 2330 持有中
  When 使用者點出場連結
  Then 說明「沒有持有中的 2330」，並提供新增一筆

Scenario: 別人的或已不在紀錄中
  Given 連結是別人的機器人，或那一輪已被刷掉
  When 使用者點連結
  Then 說明找不到這一輪，並提供手動記一筆
```

Scenario: 並排勝率

```gherkin
Scenario: 開倉

  When 使用者看合約交易詳情
  Then 那一筆顯示「開倉」，價格欄叫「開倉價」

Scenario: 加倉

  When 使用者看合約交易詳情

Scenario: 減倉
  Given 持倉 0.051 後反向記 0.020
  When 使用者看合約交易詳情
  Then 那一筆顯示「減倉」，價格欄叫「平倉價」

Scenario: 平倉
  Given 持倉 0.031 後反向記 0.031
  When 使用者看合約交易詳情
  Then 那一筆顯示「平倉」

Scenario: 不再出現成交價
  When 使用者看合約的列表、記一筆、詳情

```

## 4. Business Flow & Logic

- **Core Business Rules:** 全部沿用 `go-trading` 同名切片 PRD。畫面只自己算記一筆表單上的即時預覽（持有、買進均價、止損往下幾個百分點），儲存後一律以交易服務回傳的為準。
- **Edge Cases:** 連不上交易服務時說連不上、不呈現空狀態；儲存中儲存鍵停用避免記兩筆；改過內容未儲存就離開要先在頁面內確認。

---

## 5. UI/UX Design & Interaction

- **Prototype Link:** 規劃草稿（合約日誌已照它定案）；現貨沿用同一套版面。
- 現貨列表摘要依市場分兩組（台股以新台幣、加密貨幣以 USDT）；表格欄位：#、標的、市場、狀態、來源、買進均價、賣出均價、淨損益、報酬率、標籤；持有中的損益標「浮」。
- 現貨狀態叫**持有中**、已平倉、已檢討。

---

## 6. Non-Functional Requirements

- **Performance / Compatibility:** 與合約日誌相同；窄螢幕買賣一筆一張卡。
- **Analytics / Tracking:** N/A

---

## 7. Dependencies & Risks

- **External Dependencies:** `go-trading` 同名切片的現貨日誌服務（同時開發中）。
- **Known Risks:** 後端欄位若與約定不同，需在對接時校正。

---

## 8. Appendix

- 本 PRD 自行決定的事項：現貨日誌路徑獨立於合約日誌、由頂列開關切換；列表多一個依市場篩選；台股數量輸入即時提示整數股；手續費率設定頁標明只用於合約日誌；零股與整張不另外換算，一律以股顯示。
