# 幣安自動下單設定（網頁）— Requirements Brief

## Goal

交易服務這一刀新增兩件「下單之前要準備好」的事：使用者自己的一組**幣安交易金鑰**，以及每台策略機器人上的**自動下單**開關。
**這一刀不下任何一張單**——開關打開與否，機器人仍然只送 Telegram。

網頁要讓使用者：在設定頁存入、查看、移除自己的幣安交易金鑰；在現貨與合約機器人的畫面上打開或關掉自動下單；
並且**清楚知道這個開關目前還不會真的下單**，不會誤以為機器人已經在用他的錢交易。

業務規則與拒絕一律以 `go-trading/.sdd/2026-10-01-binance-auto-order-setup/BRIEF.md` 為準。

## Requirements

### 一、設定頁：幣安交易金鑰

- 在既有設定頁（Telegram 設定所在的那一頁）多一區**幣安交易金鑰**。
- **尚未設定時**：顯示兩格輸入——**API Key** 與 **Secret Key**——與一顆存入的按鈕。
  Secret Key 輸入時以遮蔽方式顯示。
- **已設定時**：顯示 API Key 結尾 4 個字（前面遮掉）、**可交易市場**（現貨／合約／兩者）與設定時刻；
  **不顯示任何一段 Secret Key**。提供「換一組」與「移除」。
- 「換一組」一律兩格都重新填，畫面上**沒有任何一格預先填入舊值**。
- 存入時系統會先問幣安，**等待期間要讓使用者知道正在確認**，按鈕不能再按一次。
- 存不成時，把交易服務給的原因照原話顯示，且至少分得出：**金鑰不被接受**、**連不上幣安**、**等太久**、
  **沒有任何交易權限**、**系統目前存不了**；兩格必填空白時指出是哪一格。
  失敗後畫面維持**原本已存的那一組**，不顯示成「未設定」。
- 移除前先請使用者確認，並說明**所有開著自動下單的機器人會一併被關掉**。
- 在此區旁說明：可交易市場只記存入當下的狀態，在幣安那邊改了權限要回來重存一次。

### 二、機器人畫面：自動下單開關

- 現貨機器人與合約機器人的**詳細頁**都有自動下單開關，**列表**上看得出哪幾台開著。
- 新建機器人的畫面**不需要**這個開關——新機器人一律關閉，建立後到詳細頁再開。
- 開關**隨時可操作**，不因機器人執行中或已停止而停用。
- **打開被拒**時照原話顯示原因，至少分得出：**要先完成幣安交易金鑰設定**（並提供前往設定頁的路）、
  **這組金鑰沒有現貨（或合約）交易權限**。開關回到關閉。
- **關掉永遠可以**，畫面不得加任何前提或擋住關掉的動作。
- 開關旁一律標示**「尚未生效：目前機器人仍只送 Telegram 通知，不會下單」**，直到下一個切片真的開始下單為止。

### 三、金鑰變動後的機器人狀態

- 移除或換掉金鑰之後，機器人畫面上的開關要反映交易服務的最新狀態（被自動關掉的就顯示關閉），
  不能停留在操作前的樣子。

## Examples (Specification by Example)
Each example lists **only** the data that affects the behavior — nothing more.

| # | Given (only relevant data) | When | Then |
|---|---|---|---|
| 1 (happy) | 尚未設定 | 在設定頁填入兩格、按存入，幣安說有效、可交易：現貨 | 等待中顯示正在確認；完成後顯示 API Key 結尾 4 個字、可交易市場：現貨 |
| 2 (exception) | 尚未設定 | Secret Key 留空就按存入 | 指出 Secret Key 必須填 |
| 3 (exception) | 已存一組（結尾 `a1b2`） | 換一組，幣安說金鑰不被接受 | 顯示「金鑰不被接受」；畫面仍顯示結尾 `a1b2` 那一組 |
| 4 (exception) | — | 存入時幣安說兩種交易權限都沒開 | 顯示「這組金鑰沒有任何交易權限」 |
| 5 (boundary) | 已存一組 | 點「換一組」 | 兩格都是空的，沒有預填任何舊值 |
| 6 (happy) | 已存一組；兩台機器人開著自動下單 | 點移除並確認 | 設定區回到未設定；那兩台的開關都顯示關閉 |
| 7 (exception) | 沒有金鑰 | 在現貨機器人詳細頁打開自動下單 | 顯示要先完成幣安交易金鑰設定並提供前往設定頁的路；開關回到關閉 |
| 8 (exception) | 金鑰可交易：現貨 | 在合約機器人詳細頁打開自動下單 | 顯示這組金鑰沒有合約交易權限；開關回到關閉 |
| 9 (happy) | 金鑰可交易：現貨；現貨機器人執行中 | 打開自動下單 | 成功；開關旁標示「尚未生效」 |
| 10 (happy) | 任何情況 | 關掉自動下單 | 成功，沒有任何確認或前提擋住 |
| 11 (boundary) | 舊金鑰可交易現貨、合約；合約機器人甲、現貨機器人乙開著 | 換存只開現貨的新金鑰 | 存入成功；之後看甲顯示關閉、乙顯示開著 |

## Out of Scope

- 真的下單、顯示下單結果或成交紀錄。
- 一位使用者多組金鑰，或不同機器人選不同金鑰。
- 在網頁上提醒「不要開提現權限」以外的權限稽核。
- 被自動關掉的機器人的通知或記號（交易服務尚未決定是否提供）。

## Open Decisions

- 換存或移除金鑰後，若交易服務回報「哪幾台被自動關掉」，是否要在設定頁直接列出。
- 「尚未生效」的確切措辭與位置（開關旁一行小字，或整區提示）。
- 列表上「開著自動下單」用什麼方式標出。

## Context / Background

- 設定頁的互動沿用 Telegram 設定那一區：只顯示結尾、不回填、失敗不動已存設定、移除不存在的設定不算失敗。
- 與 Telegram 不同：Secret Key 連結尾都不顯示；存入當下就要等幣安回覆，所以需要等待狀態。
- 「尚未生效」的標示是為了避免使用者打開開關後，誤以為機器人已經在替他交易。
