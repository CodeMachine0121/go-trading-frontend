# Product Requirements Document (PRD)

**Feature:** 策略與執行參數分離（操作介面）
**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** 前端（go-trading-frontend）、後端（go-trading）

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:**
  指標計算畫面上的「彙總刻度」旁邊寫著一句道歉：**目前計算仍以五分鐘執行**。
  那句話是上一個切片刻意留下的誠實——當時系統只算得動五分鐘——但誠實不能代替可用：
  使用者挑了「一小時」，看到的仍是五分鐘算出來的數字。

  「計算根數」與它一起被記在策略身上，於是同一套算法想用兩種粗細看，
  就得存成兩支內容一字不差、只有取數不同的策略，策略清單被同一套算法的變體塞滿。

- **Expected Outcome:**
  彙總刻度真的生效，那句道歉消失。同一支策略能在不同粗細下反覆執行，不必為每一種粗細各存一支。
  結果自己說出這次實際採用的粗細，使用者不必信任這件事。

- **Out of Scope:**
  - 在 K 線圖表上套用策略、把指標值畫出來——下一個切片。
  - 讓使用者指定「算到哪個時間為止」——這個畫面一律算到現在。
  - 呈現「這次讀了哪幾根」——要用它的是圖表那一邊。
  - 替既有策略補回那兩樣。
  - 交易標的、算式內容、指標值種類、存檔／改名／刪除的任何行為改動。

---

## 2. User Personas

- **Primary Role(s):** 在操作台上寫策略並拿它去算的人（本專案作者本人）。
- **Usage Context:** 一次互動一次回覆的即時操作；
  同一支算法在一次工作中常會用好幾種粗細各看一次。

## 3. User Stories & Acceptance Criteria

### US-01 — 一支策略只記著算法 [priority: P0]

**As a** 寫策略的人，**I want** 儲存與載入只動算法本身，
**so that** 我的策略清單上每一列都是一套不同的算法，而不是同一套算法的不同看法。

```gherkin
Scenario: 另存為新策略時只存下算法
  Given 畫面上的算式內容為「取收盤價平均」、指標值種類為一串數字
  And 畫面上的彙總刻度為一小時、計算根數為 60
  When 另存為新策略並取名「均線」
  Then 存下去的內容只有名稱「均線」、該段算式與一串數字
  And 一小時與 60 沒有被存進那一支策略

Scenario: 載入一支策略帶進來的只有算法
  Given 一支記著算式「取最高價」與指標值種類為一個數字的策略
  When 載入那一支策略
  Then 算式內容變成「取最高價」
  And 指標值種類變成一個數字

Scenario: 讀回一支策略時沒有取數計畫可讀
  Given 一支已經存下來的策略
  When 再讀它一次
  Then 讀回來的是策略名稱、指標算式與指標值種類
  And 回覆中不出現彙總刻度，也不出現計算根數
```

### US-02 — 載入策略不動這一次的執行設定 [priority: P0]

**As a** 正在用某個粗細研究一件事的人，**I want** 換一支算法不要把我的取數設定換掉，
**so that** 我不必每換一支策略就把粗細與根數重挑一次。

```gherkin
Scenario: 載入策略不動彙總刻度與計算根數
  Given 畫面上的彙總刻度為一小時、計算根數為 60
  When 載入另一支策略
  Then 彙總刻度仍是一小時
  And 計算根數仍是 60
  And 只有算式內容與指標值種類被換掉

Scenario: 載入策略不動交易標的
  Given 畫面上的交易標的為某一檔
  When 載入另一支策略
  Then 交易標的不變

Scenario: 開一份新的空白策略也不動執行設定
  Given 畫面上的彙總刻度為四小時、計算根數為 60
  When 開一份新的空白策略
  Then 算式內容清空、指標值種類回到預設
  And 彙總刻度仍是四小時
  And 計算根數仍是 60
```

### US-03 — 什麼才算未儲存的變更 [priority: P0]

**As a** 會被確認對話框擋下來的人，**I want** 只有真的會弄丟東西時才問我，
**so that** 那個對話框出現時我會認真讀它。

```gherkin
Scenario: 改動彙總刻度不算未儲存的變更
  Given 已載入某一支策略，之後算式內容與指標值種類一個字都沒改
  When 把彙總刻度從五分鐘改成一小時，接著挑另一支策略
  Then 直接載入另一支，不出現放棄變更的確認

Scenario: 改動計算根數不算未儲存的變更
  Given 已載入某一支策略，之後算式內容與指標值種類一個字都沒改
  When 把計算根數從 20 改成 60，接著挑另一支策略
  Then 直接載入另一支，不出現放棄變更的確認

Scenario: 改動算式內容算未儲存的變更
  Given 已載入某一支策略
  When 改動算式內容，接著挑另一支策略
  Then 出現放棄變更的確認
  And 未確認前算式內容不被覆蓋

Scenario: 改動指標值種類算未儲存的變更
  Given 已載入某一支策略
  When 把指標值種類換成另一種，接著挑另一支策略
  Then 出現放棄變更的確認

Scenario: 還沒載入過任何策略且算式空白時不問
  Given 還沒載入過任何策略，且算式內容是空白
  When 挑一支策略
  Then 直接載入，不出現放棄變更的確認
```

### US-04 — 彙總刻度真的生效 [priority: P0]

**As a** 拿策略去算的人，**I want** 我挑的粗細真的被拿去算，
**so that** 我看到的數字就是我以為自己在看的那個數字。

```gherkin
Scenario: 以挑選的粗細執行計算
  Given 畫面上的彙總刻度為一小時、計算根數為 24
  When 執行計算
  Then 這次計算以一小時的彙總刻度、24 根執行

Scenario: 挑最細的那一種
  Given 畫面上的彙總刻度為五分鐘
  When 執行計算
  Then 這次計算以五分鐘執行

Scenario: 什麼都沒挑就是五分鐘
  Given 剛進入畫面，彙總刻度未曾被更動
  When 執行計算
  Then 這次計算以五分鐘執行

Scenario: 那句道歉的話不再出現
  Given 停留在指標計算畫面
  When 看彙總刻度欄位的說明
  Then 說明中不出現「目前計算仍以五分鐘執行」這類尚未生效的字眼
```

### US-05 — 結果說出它用的是多粗 [priority: P0]

**As a** 看結果的人，**I want** 結果自己說出這次採用的粗細，
**so that** 「安靜地用了另一種刻度」這種錯看得出來，而不必靠信任。

```gherkin
Scenario: 結果寫出這次採用的彙總刻度
  Given 以一小時執行了一次計算
  When 看結果
  Then 結果上寫著這次採用的彙總刻度是一小時
  And 它與實際採用根數並列

Scenario: 最細的那一種也照樣寫出來
  Given 以五分鐘執行了一次計算
  When 看結果
  Then 結果上寫著這次採用的彙總刻度是五分鐘

Scenario: 寫的是系統回報的刻度，不是送出時挑的那一個
  Given 送出時挑的是一小時
  And 系統回報它實際採用的是五分鐘
  When 看結果
  Then 結果上寫著五分鐘

Scenario: 一個指標都沒算出來時照樣寫得出粗細
  Given 一次算出零個指標的計算，以一小時執行
  When 看結果
  Then 結果上仍寫著一小時

Scenario: 計算失敗時沒有粗細可說
  Given 一次失敗的計算
  When 看畫面
  Then 完全不呈現結果
  And 畫面上沒有「這次採用的彙總刻度」
```

### US-06 — 計算說明要跟上實際規則 [priority: P1]

**As a** 讀畫面上那句說明的人，**I want** 它講的是系統實際在做的事，
**so that** 我不會照著一句過期的規則去理解算出來的數字。

```gherkin
Scenario: 說明講的是走完的那幾格
  Given 停留在指標計算畫面
  When 看計算說明
  Then 說明中出現「只採用已經走完的那幾格」的意思

Scenario: 不再說「排除最新一根」
  Given 停留在指標計算畫面
  When 看計算說明
  Then 說明中不出現「排除最新一根」
```

### US-07 — 其餘一字不動 [priority: P0]

**As a** 已經習慣這個畫面的人，**I want** 其他行為完全不變，
**so that** 這次改動不必重新學任何東西。

```gherkin
Scenario: 存回使用中的那一支
  Given 有使用中的策略，且算式內容改過了
  When 儲存
  Then 存回那一支，並顯示已儲存的訊息

Scenario: 名稱被佔用時就地說明
  Given 另存為新策略時取了一個已被使用的名稱
  When 送出
  Then 就地說明該名稱已被使用
  And 已填的內容保留不清空

Scenario: 算式跑不起來
  Given 一段跑不起來的算式
  When 執行計算
  Then 呈現算式的問題
  And 不呈現任何結果

Scenario: 載入一支認不出外框的策略
  Given 一支算式認不出外框的策略
  When 載入它
  Then 整段原文帶進編輯區
  And 告知它看起來不是在這裡寫出來的
```

## 4. Business Flow & Logic

**Core Business Rules**

- **策略記住三樣**：策略名稱、指標算式、指標值種類。
- **執行設定三樣**：交易標的、彙總刻度（五選一、未挑為五分鐘）、計算根數。
  它們描述「這一次要怎麼算」，不隨策略存下來、不隨策略載入被覆蓋。
- **未儲存的變更只看算法**：算式內容或指標值種類與載入當下不同才算。
- **結果帶著系統回報的彙總刻度**，與實際採用根數並列。
- **計算說明講的是「走完的刻度區間」**，不是「最新一根」。

**Edge Cases**

- 尚未載入過任何策略時，「有沒有還沒存的東西」沿用既有規則：只看算式內容是否為空白。
- 一次算出零個指標：仍呈現實際採用根數、指標值種類與這次採用的彙總刻度。
- 計算失敗：不呈現任何結果，也就沒有「這次採用的彙總刻度」可說。

## 5. UI/UX Design & Interaction

- 彙總刻度與計算根數**位置不變**，仍與交易標的並列在「執行」那一欄。
  它們的歸屬變了，擺法沒變——使用者不必重新找。
- **彙總刻度的說明改寫**：刪掉「目前計算仍以五分鐘執行」，改成說明它屬於這一次計算。
- **計算說明改寫**：從「一律排除最新一根」改成「只採用已經走完的那幾格」。
- **結果列多一項**：這次採用的彙總刻度，與「實際採用 N 根」並列。
- 另存為新策略對話框的說明改為只提算式與指標值種類。

## 6. Non-Functional Requirements

- **Performance:** 無變化，仍是一次互動一次請求。
- **Security:** 無變化。
- **Compatibility:** 依賴系統端同批的破壞性變更；兩邊一起更新，不做版本並存。
- **Analytics / Tracking:** N/A。

## 7. Dependencies & Risks

- **External Dependencies:** 後端 `go-trading` 的同名切片（策略少兩樣、計算收下彙總刻度、
  回覆帶出實際採用的刻度）。**必須先部署後端**。
- **Known Risks:**
  - 既有策略在系統那頭已經失去那兩樣，介面上載入時自然也帶不進來——預期行為，不是遺失。
  - 彙總刻度從此真的生效，同一支策略以相同根數執行會得到**與先前不同的數字**（先前一律五分鐘）。
    這正是修好它的意義，但第一次看到時可能誤以為算錯——因此結果必須寫出這次用的是多粗。
  - **本切片推翻了一個既有切片的決定**（`2026-09-03-strategy-library` 的「彙總刻度只記錄不生效」）。
    通用語言地圖上對應的那幾列必須同步改掉，否則地圖會與程式碼漂移。
