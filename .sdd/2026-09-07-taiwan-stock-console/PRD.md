## 1. Background & Goal (Why & Goal)

- **Problem Statement:**
  這台終端機到目前為止只看得到一個市場，因此有三件事從來不必問：
  交易標的一定看得到即時更新、K 線的每一個欄位一定有值、沒有新資料就是出了什麼問題。

  台股接進來之後，這三件事全部不再成立。而這台終端機既有的四種狀態
  （載入中／查無資料／被拒絕／連不上）**共同的前提是「沒有東西就是不正常的」**——
  台股收盤時沒有新資料是正常的，某些交易標的沒有即時更新也是正常的。
  把正常的事呈現成那四種，等於天天對使用者謊報一次故障；
  而真正的故障混在裡面之後，就再也沒有人會認真看待任何一個提示。

  同時，後端的觀察清單已經改得動了。前端不接的話，使用者得自己去動後端的資料——
  那等於這個能力做了等於沒做。

- **Expected Outcome:**
  - 使用者在**挑交易標的之前**就看得出它是哪個市場、有沒有即時更新。
  - 台股收盤時，畫面說的是**「收盤中」**，不是四種故障提示的任何一種。
  - 台股的成交額三欄呈現成**「沒有這一項」**，與 `0` 一眼分得出來。
  - 觀察清單從畫面上改得動，改不成功時說得出**是哪一種**不成功。

- **Out of Scope:**
  - **決定哪幾檔有即時更新**——名額怎麼分是後端的事，畫面只照實說出來。
  - **調整觀察清單的順序**——後端不提供，畫面也不做。
  - **顯示「目前正在跟哪幾檔」的完整名單。**
  - **台股與加密貨幣同時顯示在同一張圖上比較。**
  - **台股專屬的行情**（法人買賣超、融資融券、除權除息、成交明細、掛單簿）。
  - **成交量的單位換算**——照後端給的原樣顯示，不換算成「張」。
  - **台股交易時段與休市日的維護介面。**
  - **收盤倒數、開盤提醒**等與時間有關的提示。
  - **觀察清單的批次匯入匯出。**
  - **K 線圖表既有的取資料規則、彙總刻度自動選擇、指標套用與重算**——一律沿用。
  - **新增／修改 K 線表單改成挑市場**——維持手打，見 §7 Known Risks。

## 2. User Personas

- **Primary Role(s):** 看盤的人（專案作者本人）。他同時是決定要追蹤哪些標的的人，
  也是在圖表上看它們的人。
- **Usage Context:**
  桌面瀏覽器，深色的操作台介面。台股的交易時段與他的清醒時間高度重疊；
  加密貨幣則整夜都在動，所以他常在台股收盤之後仍然開著這個畫面。

## 3. User Stories & Acceptance Criteria

### US-01 — 交易標的看得出它屬於哪個市場 [priority: P0]

**As a** 看盤的人，**I want** 挑交易標的時就看得出它是哪個市場，
**so that** 我不必挑完之後才回頭理解畫面為什麼長這樣。

```gherkin
Scenario: 兩個市場的標的並排時看得出差別
  Given 清單裡有台股的 2330 與加密貨幣的 BTCUSDT
  When 打開交易標的的選單
  Then 2330 標示為台股
  And BTCUSDT 標示為加密貨幣

Scenario: 只看某一個市場
  Given 清單裡有十檔台股與三檔加密貨幣
  When 使用者選擇只看台股
  Then 選單上只剩那十檔台股

Scenario: 換到另一個市場就換到那個市場的標的
  Given 目前選著 BTCUSDT
  And 清單裡的第一檔台股是 2330
  When 使用者切換成只看台股
  Then 目前選著的變成 2330
  And 選單上看不到 BTCUSDT

Scenario: 目前選著的那一檔就屬於切過去的市場
  Given 目前選著 2454
  When 使用者切換成只看台股
  Then 目前選著的仍然是 2454

Scenario: 該市場一檔都沒有
  Given 清單裡一檔台股都沒有
  When 使用者選擇只看台股
  Then 畫面說明目前沒有任何台股，並指出可以先去觀察清單加入一檔
  And 選單上一檔都沒有，也不留下別的市場的標的充數
  And 圖表說明還沒有行情可以畫，而不是指責使用者沒有指定交易標的
```

### US-02 — 把交易標的加進觀察清單 [priority: P0]

**As a** 看盤的人，**I want** 從畫面把一檔加進觀察清單，
**so that** 我不必為了多追蹤一檔股票去動後端的資料。

```gherkin
Scenario: 加一檔存在的台股
  Given 2330 不在觀察清單上
  When 使用者指定台股、填入 2330 並送出
  Then 加入成功
  And 觀察清單上立刻出現 2330

Scenario: 代號在那個市場找不到
  Given 9999 在台股不存在
  When 使用者指定台股、填入 9999 並送出
  Then 畫面說明這個代號在台股找不到
  And 觀察清單維持原狀

Scenario: 後端問不到那個市場
  Given 後端此刻問不到台股的行情
  When 使用者指定台股、填入 2330 並送出
  Then 畫面說明稍後再試
  And 這句話與「代號找不到」明顯不是同一句

Scenario: 重複加同一檔
  Given 2330 已經在觀察清單上
  When 使用者再一次加入 2330
  Then 觀察清單上的 2330 維持一筆
  And 畫面不呈現成錯誤

Scenario: 代號空白
  Given 代號欄位是空白的
  When 使用者送出
  Then 畫面就地說明代號必填
  And 不向後端送出任何東西

Scenario: 畫面說得出改動不是立刻生效的
  Given 使用者正在看觀察清單畫面
  When 畫面呈現出來
  Then 畫面說明改動最多要等一輪才會生效
```

### US-03 — 把交易標的從觀察清單拿掉 [priority: P0]

**As a** 看盤的人，**I want** 拿掉一檔之前先被告知 K 線都會留著，
**so that** 我按下去之前不必猶豫。

```gherkin
Scenario: 拿掉一檔，且被告知資料會留著
  Given 2330 在觀察清單上
  When 使用者按下移除
  Then 跳出確認，並說明已經抓回來的 K 線都會留著
  And 確認之後觀察清單上不再有 2330

Scenario: 取消移除
  Given 移除的確認已經跳出
  When 使用者取消
  Then 2330 仍在觀察清單上

Scenario: 拿掉最後一檔
  Given 觀察清單上只剩一檔
  When 使用者把它拿掉
  Then 畫面說明目前沒有任何追蹤中的交易標的
  And 不呈現成錯誤

Scenario: 拿掉之後它的 K 線還查得到
  Given 2330 剛被從觀察清單拿掉
  When 使用者去看 K 線
  Then 2330 仍然挑得到
  And 它以前的 K 線照樣查得出來
```

**As a** 看盤的人，**I want** 在挑之前就知道這一檔有沒有即時更新，
**so that** 我不會盯著一張看起來正常、其實不會動的圖。

```gherkin
Scenario: 挑之前就看得出有即時更新

  When 打開交易標的的選單
  Then 2330 標示為有即時更新

Scenario: 挑之前就看得出沒有即時更新
  Given 2454 沒有即時更新
  When 打開交易標的的選單
  Then 2454 標示為沒有即時更新

Scenario: 看一檔沒有即時更新的台股
  Given 2454 沒有即時更新
  When 使用者在圖表上看 2454
  Then 畫面說明它沒有即時更新、資料五分鐘更新一次
  And 圖照常畫出手上有的 K 線

Scenario: 沒有即時更新與即時斷掉是兩句不同的話
  Given 使用者正在看 2330，它原本有即時更新

  Then 畫面說的是即時更新已停止、正在接回來

Scenario: 拿到名額之後說明自己消失
  Given 2454 原本沒有即時更新
  And 它後來拿到了即時名額

  Then 那句說明不再出現
  And 圖上最後那一根跟著市場動
```

**As a** 看盤的人，**I want** 收盤時畫面說的是「收盤中」，
**so that** 我不會把每天晚上都當成故障。

```gherkin
Scenario: 收盤中看台股的圖
  Given 台股目前收盤中
  When 使用者在圖表上看 2330
  Then 畫面說明台股目前收盤中
  And 圖照常顯示手上有的 K 線

Scenario: 看到收盤那一刻
  Given 使用者正在看 2330 的圖

Scenario: 開盤之後說明自己消失
  Given 收盤中的說明正掛著
  When 台股開盤
  Then 那句說明不再出現
  And 圖上最後那一根繼續跟著動
  And 使用者不必做任何事

Scenario: 加密貨幣不出現收盤的說明
  Given 台股目前收盤中

  Then 畫面不出現任何與收盤有關的說明

Scenario: 收盤時的說法壓過即時停止的說法
  Given 台股目前收盤中

  And 不同時再說一次即時更新已停止
```

### US-07 — 會收盤的市場可以要求立刻更新 [priority: P0]

**As a** 看盤的人，**I want** 對一檔台股按一下就把它的 K 線拉到最新，
**so that** 我不必為了看今天的資料等下一輪、或去重開整個系統。

台股收盤之後，每五分鐘一輪已經沒有東西可收了——那正是最想看今天資料的時候。
加密貨幣沒有這個問題：它永遠只差一輪就跟上了。

```gherkin
Scenario: 會收盤的市場給這顆按鈕
  Given 目前看的是一檔台股
  When 進入 K 線圖表
  Then 畫面上有「立刻更新」

Scenario: 不收盤的市場不給這顆按鈕
  Given 目前看的是一檔加密貨幣
  When 進入 K 線圖表
  Then 畫面上沒有「立刻更新」

Scenario: 按下去就補回來，並說補到幾根
  Given 目前看的是一檔台股，它缺三根
  When 使用者按「立刻更新」
  Then 畫面說補回三根
  And 圖上出現剛補回來的那幾根

Scenario: 已經是最新的
  Given 目前看的那一檔沒有任何缺口
  When 使用者按「立刻更新」
  Then 畫面說已經是最新的了，沒有可補的
  And 那不呈現成一個錯誤

Scenario: 補不回來
  Given 行情來源此刻問不到
  When 使用者按「立刻更新」
  Then 畫面說補不回來，並附上後端說的原因
  And 圖照樣顯示手上有的

Scenario: 補的時候按不出第二次
  Given 使用者已經按下「立刻更新」，還沒補完
  When 使用者再按一次
  Then 按不下去
```

## 4. Business Flow & Logic

**Flow（挑交易標的）:**

1. 進入任何一個要讀行情的畫面，取回可查交易標的清單。
2. 每一檔帶著：所屬市場、是否在交易時段內、是否有即時更新、是否追蹤中。
3. 使用者可以只看某一個市場；切過去就換到那個市場的標的上，該市場沒有標的時一檔都不選。

**Flow（加進觀察清單）:**

1. 使用者指定市場與代號。
2. 代號空白 → 就地擋下，不送出。
3. 送出 → 後端可能以三種方式拒絕：代號在該市場找不到、後端問不到那個市場、其他。
   前兩種各自說一句自己的話。
4. 成功 → 清單立刻重取，並保留「改動最多等一輪才生效」的常駐說明。

**Flow（從觀察清單拿掉）:**

1. 按下移除 → 跳出確認，訊息中明說 K 線都會留著。
2. 取消 → 什麼都沒發生。
3. 確認 → 送出，成功後清單立刻重取。

**Flow（圖表上的一句話）:**

1. 這一檔的市場不在交易時段內 → 說「收盤中」。
2. 否則，這一檔沒有即時名額 → 說「這一檔沒有即時更新，資料五分鐘更新一次」。
3. 否則，即時更新斷了 → 說「即時更新已停止，正在接回來」。
4. 否則 → 不說任何一句。

**Core Business Rules:**

- **BR-1 四種狀態的前提不再成立**：既有的載入中／查無資料／被拒絕／連不上，
  共同前提是「沒有東西就是不正常的」。收盤與沒有名額都是正常狀態，
  **不得**呈現成那四種的任何一種。
- **BR-2 一次只說一句**：圖表上的說明位置只有一個，優先序為
  **收盤中 ＞ 沒有即時名額 ＞ 即時已停止**。收盤時即時本來就會停，
  兩句一起出現會讓人以為出了兩件事。
- **BR-3 沒有名額與斷掉分開講**：一句是「等到明天也一樣」，一句是「等一下會自己好」。
  共用同一句話，等於讓一半的使用者一直在等一件不會發生的事。
- **BR-4 收盤與名額都由後端回答**：畫面不自己依時間推算收盤（它不知道休市日），
  也不自己推算名額（它不知道後端把名額給了誰）。
- **BR-5 沒有值不寫成零**：呈現成一個破折號並淡化，與 `0` 一眼分得出來。
- **BR-6 移除必須二次確認且說明資料會留著**：「移除」在直覺上接近「刪除」，
  不講清楚使用者不敢按。
- **BR-7 加入失敗要分得出是哪一種**：代號找不到（使用者能自己修）與
  後端問不到市場（等一下再試）是兩句話。
- **BR-8 改動不是立刻生效**：常駐說明；**不顯示倒數**——後端沒有告訴畫面
  距離下一輪還有多久，算出來的數字會是編的。
- **BR-9 市場鍵決定看哪個市場**：切換市場時，目前選著的那一檔若不屬於該市場，
  就換成該市場的第一檔；該市場一檔都沒有時一檔都不選。目前選著的那一檔本來就屬於
  該市場時不動它。
  留著一檔別的市場的標的，畫面就會說謊——分頁寫著台股，圖上畫的是加密貨幣。
- **BR-14 名字由後端給，畫面不翻譯也不編**：畫面不知道 2330 是誰。
  沒有名字的市場留空，**不拿代號充當名字**——代號本來就在旁邊了。
- **BR-15 怎麼唸一檔只決定一次**：三個畫面都要唸它，各自接一份「有名字就接上去」的話，
  遲早會有一個在沒有名字的時候多一個空格。
- **BR-11 立刻更新只給會收盤的市場**：判準是**這個市場會不會收盤**（由後端回答），
  不是「現在有沒有開」——後者在收盤的每個夜裡都成立，卻在加密貨幣身上永遠不成立，
  按鈕會在錯的地方出現、又在錯的地方消失。
- **BR-12 補完一定要重畫**：補齊寫的是後端的資料，畫面手上那批是補齊之前取的。
  不重取的話，剛補回來的那幾根一根都不會出現，按了跟沒按看起來一模一樣。
- **BR-13 補到零根也要說**：那是常見的答案（手上已經是最新的），
  不說出來的話，看的人分不出「按了沒事」與「按了沒反應」。
- **BR-10 加入時不即時查詢**：一律等到送出才向後端確認。打字途中的每一個前綴都是
  「找不到」，會一直閃紅字；而且每一次按鍵都向行情來源問一次，會撞上它的用量上限。

**Edge Cases:**

- **清單取不到** → 沿用既有做法：說明取不到，目前那一檔照樣顯示著。
- **觀察清單是空的** → 說明目前沒有任何追蹤中的交易標的，不呈現成錯誤。
- **加入送出中再按一次** → 送出期間按鍵停用，不送出第二次。
- **後端沒有設定台股金鑰** → 加入台股會得到「稍後再試」那一句。這是設定沒給，
  不是使用者打錯，所以說法與「代號找不到」不同。
- **一檔標的既不在交易時段、又沒有名額** → 只說收盤中（BR-2）。

## 5. UI/UX Design & Interaction

- **觀察清單是自己的一頁。** 它是自己的資源，而既有的四個畫面
  （K 線瀏覽、K 線圖表、指標計算、行情對話）都已經滿了。
- **市場篩選是一組切換鍵**（全部／台股／加密貨幣），放在挑交易標的的欄位上方。
- **圖表上的那一句話沿用即時更新停止時既有的位置**——同一個位置、一次一句。
- **「沒有這一項」是一個破折號並淡化**，滑過去說得出為什麼。
- **四種既有狀態的呈現方式一律沿用**，本切片不動它們。

## 6. Non-Functional Requirements

- **NFR-1 挑標的不變慢**：多帶四個欄位不得讓交易標的清單的取回明顯變慢；
  篩選在畫面這一側完成，不重新向後端取一次。
- **NFR-2 不多打後端**：加入觀察清單只在送出時向後端確認一次，
  打字途中不查詢（BR-10）。
- **NFR-3 沿用既有的樣式系統**：顏色、間距、字級一律用既有的 token，
  需要新的值先補進 token 檔。
- **NFR-4 深色操作台一致性**：新畫面與既有畫面看起來是同一台終端機。

## 7. Dependencies & Risks

- **External Dependencies:**
  - 後端 `go-trading` 的 `.sdd/2026-09-07-taiwan-stock-market-data/` 切片：
    四個附帶欄位、觀察清單的兩條路、第四種即時更新狀態。
    **本切片的每一條驗收條件都依賴它已經上線。**

- **Known Risks:**
  - **新增／修改 K 線的表單仍然手打交易標的**，而後端現在需要知道標的屬於哪個市場。
    手動建出來的標的會被後端讀成加密貨幣（它對沒記市場的資料就是這樣讀的）。
    本切片刻意不動這個表單——它正是新的交易標的誕生的地方，改成只能挑市場會擋住那條路。
    **該回頭處理的訊號**：有人用這個表單建了台股的 K 線，然後發現它被當成加密貨幣。
  - **「改動最多等一輪」沒有倒數**，使用者不知道還要等多久。
    這是刻意的：後端沒告訴畫面下一輪何時到，算出來的數字會是編的。
  - **台股收盤的判斷完全仰賴後端**。後端答錯（例如休市日推定錯誤），畫面就會照著錯。
    這是刻意的取捨——畫面自己推算會錯得更頻繁。
