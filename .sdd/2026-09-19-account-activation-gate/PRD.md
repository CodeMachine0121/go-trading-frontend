# Product Requirements Document (PRD)

**Feature:** 等待開通的畫面
**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal

- **Problem Statement:**
  後端現在把新帳號擋在門外，直到有人親自放行。這個操作台不知道，
  所以會把一個什麼都做不了的人放進操作台，讓他在每一顆按鈕上各撞一次牆。

- **Expected Outcome:**
  1. 還沒開通的人進門之後**只看得到一頁**，而且**跳不掉**。
  2. 那一頁說得出：他在等、寄到哪、主旨照抄什麼。
  3. 主旨**一字不差**地複製得走，也開得成一封填好的信。
  4. 被放行之後，按一下就進得去，**不必重新登入**。
  5. 已經開通的人**到不了**那一頁。
  6. 等的人**登得出去**。

- **Out of Scope:** 在這一側放行任何人；代寄那封信；被放行的通知；自動輪詢。

---

## 2. User Personas

- **Primary Role:** **剛建立帳號、正在等放行的使用者。**
- **Usage Context:**
  他人在瀏覽器前，兩秒前才按下「建立帳號」。接下來他要離開這個網站去開自己的信箱，
  然後回來反覆重整想知道放行了沒。因此這一頁被讀到的次數遠多於一次，
  而**「重新檢查」比什麼都重要**。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 還沒開通就只看得到那一頁 [priority: P0]

**As a** 還沒被放行的使用者，**I want** 進門之後只看到一個說明我在等什麼的畫面，
**so that** 我不會在一個什麼都按不動的操作台裡到處撞牆。

```gherkin
Scenario: 建立帳號之後直接停在等待開通那一頁
  Given 我剛用一個沒人用過的電子郵件與密碼建立帳號
  And 這個帳號是待開通
  When 建立完成
  Then 我看到等待開通那一頁

Scenario: 從首頁進來也被帶到那一頁
  Given 我是待開通的使用者，而且已經登入
  When 我打開首頁
  Then 我看到等待開通那一頁

Scenario: 手動打網址一樣跳不掉
  Given 我是待開通的使用者，而且已經登入
  When 我直接打開機器人那一頁的網址
  Then 我看到等待開通那一頁

Scenario: 登入頁也帶回那一頁，而不是首頁
  Given 我是待開通的使用者，而且已經登入
  When 我打開登入頁
  Then 我看到等待開通那一頁

Scenario: 沒登入的人看不到那一頁
  Given 我完全沒有登入
  When 我打開等待開通那一頁
  Then 我看到登入頁
```

### US-02 — 那一頁說得出我該做什麼 [priority: P0]

**As a** 正在等的使用者，**I want** 看到要寄去哪、主旨寫什麼，並且能原字帶走，
**so that** 我寄出去的那封信，收信的人認得出是我在申請。

```gherkin
Scenario: 信箱與主旨都原字顯示
  Given 我是待開通的使用者
  And 系統說要寄到「gatekeeper@example.com」，主旨是「申請：alice@example.com」
  When 我看等待開通那一頁
  Then 畫面上寫著「gatekeeper@example.com」
  And 畫面上寫著「申請：alice@example.com」

Scenario: 主旨複製得走，一字不差
  Given 我是待開通的使用者
  And 主旨是「申請：alice@example.com」
  When 我按下「複製主旨」
  Then 剪貼簿裡是「申請：alice@example.com」

Scenario: 一鍵開出一封填好的信
  Given 我是待開通的使用者
  And 系統說要寄到「gatekeeper@example.com」，主旨是「申請：alice@example.com」
  When 我看那顆「寄出申請」的動作
  Then 它開出的信，收件人是「gatekeeper@example.com」、主旨是「申請：alice@example.com」
```

### US-03 — 被放行之後立刻進得去 [priority: P0]

**As a** 剛被放行的使用者，**I want** 按一下就進得去，
**so that** 我不必重新登入，也不必猜自己要做什麼。

```gherkin
Scenario: 放行之後按重新檢查就進得去
  Given 我是待開通的使用者，停在等待開通那一頁
  And 管理者剛剛把我改成已開通
  When 我按下「重新檢查」
  Then 我看到操作台首頁

Scenario: 還沒被放行就留在原地
  Given 我是待開通的使用者，停在等待開通那一頁
  And 管理者還沒把我改成已開通
  When 我按下「重新檢查」
  Then 我仍然看到等待開通那一頁
  And 畫面上仍然寫著要寄去的信箱與主旨

Scenario: 已經開通的人到不了那一頁
  Given 我是已開通的使用者，而且已經登入
  When 我直接打開等待開通那一頁的網址
  Then 我看到操作台首頁
```

### US-04 — 等的人也走得掉 [priority: P1]

**As a** 正在等的使用者，**I want** 在這一頁登得出去，
**so that** 我想換一個帳號時不會被困住——這一頁是我唯一到得了的地方。

```gherkin
Scenario: 在等待開通那一頁登出
  Given 我是待開通的使用者，停在等待開通那一頁
  When 我按下「登出」
  Then 我看到登入頁
```

## 4. Business Flow & Edge Cases

1. 建立帳號 → 自動登入 → 開通狀態是待開通 → **被帶到等待開通那一頁**。
2. 離開網站，用自己的信箱把那封信寄出去。
3. 管理者放行（在這一側看不到、也做不到的一步）。
4. 回來按「重新檢查」→ 進操作台。

| 情況 | 行為 |
| :--- | :--- |
| 重整頁面 | 重新確認一次，還在等就留在那一頁 |
| 連不上後端 | 與今天一樣：帶回登入頁並在那裡說明，不是白畫面 |
| 剪貼簿不給用 | 顯示複製失敗，並請他手動選取那一段——主旨仍然在畫面上 |
| 已開通的人打那個網址 | 回首頁 |
| 沒登入的人打那個網址 | 回登入頁 |

## 5. UI/UX

- **一張置中的卡片**，與登入畫面同一個形狀與同一組樣式 token：
  它們是同一類畫面——**還沒進門的人在看的那一頁**，所以**都不套操作台外框**。
- 卡片內容由上而下：品牌標記 → 標題「等待開通」→ 一句說明 →
  **收件信箱**（可複製）→ **主旨**（可複製，等寬字，可整段選取）→
  主要動作「寄出申請」（開信）→ 次要動作「重新檢查」→ 幽靈動作「登出」。
- 主旨用**等寬字**顯示並允許換行：它含有他自己的電子郵件，可能很長，
  截斷或加省略號會讓他複製到一段不完整的字。
- 「重新檢查」進行中要看得出來，否則他會連按。

---

## 6. Non-Functional Requirements

- **把關只能有一道。** 判斷寫在全域中介層，不是每一頁各判一次——一頁忘了寫就是一個洞。
- **不輪詢。** 只有他按下去才去問後端。
- **不快取開通狀態。** 每一次確認都以後端當下的答案為準。
- 這一側**沒有任何**改得動開通狀態的路徑。

---

## 7. Dependencies & Risks

| 項目 | 說明 |
| :--- | :--- |
| 後端 | 需要 `帳號開通把關` 那個切片：目前登入者要帶開通狀態與開通指示 |
| 上線那一刻 | 現有使用者全部會看到這一頁，直到有人去資料庫放行。照實顯示即可 |
| 中介層只在瀏覽器端跑 | 沿用既有決定（見登入把關）。伺服器端算頁面碰不到瀏覽器儲存 |
