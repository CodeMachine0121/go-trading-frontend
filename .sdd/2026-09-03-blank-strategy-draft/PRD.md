Ubiquitous Language: `../UL-MAP.md`
Project: `../PROJECT.md`

---

## 1. Background & Goal (Why & Goal)

指標計算畫面上一次只有一份稿子，而那份稿子可能屬於某一支存起來的策略，也可能誰都不屬於。
目前**只有「屬於某一支」這個方向走得通**：可以從清單挑一支載入，卻沒有一條路回到「一份誰都不屬於的空白」。

於是「我想從頭寫一支新的」變成一連串手動動作——清掉算式、把三個選項各自改回預設，
而且畫面仍然認為你在改原本那一支，按下儲存就蓋掉它。這是個會弄丟別人東西的陷阱。

**目標**：把「開新檔案」這個動作補上，讓它像編輯器裡的那一顆一樣——清乾淨、解除關聯、
一次後端請求都不發。

## 2. User Personas

| Persona | 是誰 | 在這件事上要什麼 |
| :--- | :--- | :--- |
| 策略作者（本專案唯一的使用者） | 自己寫算式、自己回測的開發者 | 寫完一支之後能乾淨地開下一支，而且不會不小心蓋掉剛寫好的那一支 |

## 3. User Stories & Acceptance Criteria

### US-01 — 開一份新的空白策略 [priority: P0]

作為策略作者，我要一個「新的空白策略」的動作，
好讓我從頭寫一支新的，而不必手動清四個地方、也不怕蓋掉正在用的那一支。

```gherkin
Scenario: 清空算式並把設定帶回預設
  Given 正在用一支策略，算式是 "sum := 123.0"、指標值種類是「一串是非」、彙總刻度是「四小時」、計算根數是 45
  And 編輯區的內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 算式清空
  And 指標值種類回到預設
  And 彙總刻度回到預設
  And 計算根數回到預設的 20

Scenario: 解除與那一支的關聯
  Given 正在用一支名為「二十根均線」的策略，且內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 策略選單顯示「未使用任何策略」
  And 接著按下「儲存」時，畫面問一個新名字，而不是直接存回「二十根均線」

Scenario: 交易標的不受影響
  Given 使用者正在看 "ETHUSDT"，且編輯區的內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 交易標的仍是 "ETHUSDT"

Scenario: 上一次的計算結果不留在畫面上
  Given 上一次計算算出了一個指標值，且編輯區的內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 畫面上不再有那一次的計算結果

Scenario: 一律說出已經開了新的一份
  Given 一支策略都還沒有，且編輯區是空的
  When 使用者按下「新的空白策略」
  Then 畫面說出已經開了一份新的空白策略
```

### US-02 — 清空之前先問過 [priority: P0]

作為策略作者，我要在編輯區還有沒存的東西時被問一次，
好讓我不會因為按錯一顆按鈕就弄丟寫到一半的算式。

```gherkin
Scenario: 有未儲存的變更時先問
  Given 編輯區的算式被改過而且還沒存
  When 使用者按下「新的空白策略」
  Then 畫面問「放棄尚未儲存的變更？」
  And 編輯區的算式一個字都沒有被清掉

Scenario: 確認放棄之後才清空
  Given 畫面正在問「放棄尚未儲存的變更？」，因為使用者按了「新的空白策略」
  When 使用者確認放棄
  Then 算式清空、設定回到預設，並解除與原本那一支的關聯

Scenario: 取消就什麼都不動
  Given 畫面正在問「放棄尚未儲存的變更？」，因為使用者按了「新的空白策略」
  When 使用者取消
  Then 編輯區的算式照原樣留著
  And 仍然屬於原本那一支策略

Scenario: 一份沒動過的空白不必問
  Given 使用者剛開了一份新的空白策略，之後一個字都沒有打
  When 使用者再按一次「新的空白策略」
  Then 畫面不問任何事，直接就是一份空白
```

### US-03 — 不碰後端 [priority: P0]

作為策略作者，我要這個動作純粹發生在畫面上，
好讓我能先開一份稿子寫著，等真的想留下來時再存。

```gherkin
Scenario: 一次請求都不發
  Given 後端留著三支策略，且編輯區的內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 後端沒有收到任何請求
  And 策略清單仍是那三支

Scenario: 後端連不上也照樣開得起來
  Given 後端連不上，且編輯區的內容與載入當下相同
  When 使用者按下「新的空白策略」
  Then 算式清空成一份空白
  And 畫面不出現任何錯誤訊息
```

## 4. Business Flow

```
按下「新的空白策略」
      │
      ├─ 編輯區有未儲存的變更？（問 Application，不自己比欄位）
      │        │
      │        ├─ 有 ──▶ 開「放棄尚未儲存的變更？」，把這件事扣住
      │        │              ├─ 確認 ──▶ 往下走
      │        │              └─ 取消 ──▶ 什麼都不動，結束
      │        │
      │        └─ 沒有 ──▶ 直接往下走
      │
      └─ 套用「一份空白的內容」（算式空白 + 三個預設值）
             ├─ 解除與策略的關聯（不再屬於任何一支）
             ├─ 清掉上一次的計算結果
             └─ 說出「已經開了一份新的空白策略」
```

## 6. 技術落點（供實作對照）

詳見 `ARCH.md`。要點：

- 「一份空白的內容是什麼」在畫面上只定義**一次**，開新的與第一次進入畫面共用它。
- 「計算根數的預設是 20」從畫面裡的字面值搬進 domain，與「彙總刻度的預設」並列。
- 「先問過」與「載入另一支」共用同一條把關路徑，不是複製一份。
