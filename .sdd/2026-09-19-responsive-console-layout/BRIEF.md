# 讓操作台在小螢幕上也能用 — Requirements Brief

## Goal

這個操作台是為了一台桌上型螢幕畫的：左邊一條側欄、中間一整片工作區、
表格與圖各自在自己的框裡捲。在那個寬度上它很好用。

換到手機上它就不是那麼一回事了——九個去處擠成頂上一條要橫著捲才找得到的窄帶，
一張十二欄的 K 線表把整頁往右撐開，設定的對話框有一半在螢幕外面，
而每一顆按鈕都還是那個「一畫面要塞得下很多東西」的尺寸，按下去常常按到隔壁。

這個切片讓同一份資料在**任何寬度**都讀得到、按得到：
導覽、資料表、圖表、助手與對話框各自在窄螢幕換一套安排；
而「一次看得多」與「手指按得準」這兩種疏密，變成整站共用的**一個**選擇，
不是每個畫面各自決定——那樣遲早會長出五種不一樣的鬆緊。

最窄要撐到手機直立（寬 390）。

## Requirements

**導覽的形狀隨寬度改變**

- 寬 1024 以下收成一顆漢堡鍵叫出的抽屜：九個去處一次全看得到，選一個就收起來。
- 點抽屜外面會把它收起來，而**不是**換到別的畫面。
- 寬 1024 起維持現在這條側欄，含「收起成只剩圖示」那顆鍵。
- 原本 1024 以下那條橫著捲的窄帶**拿掉**——九個去處在平板的寬度也塞不滿一條而不捲，
  留著它等於留下一個兩邊都不討好的中間狀態。

**疏密以寬 768 為界換一套**

- 768 以下是好按的那一套：按鈕與輸入框更高、彼此拉開，代價是一次看到的東西變少。
- 768 起收緊回現在這套：一畫面塞得下更多資料。
- 兩套之下，**一整欄數字都要維持等寬、小數點排成一條線**。
  那一欄存在的理由就是上下互相比較，疏密不該讓它歪掉。

**寬資料表在放不下時自己橫向捲**

- 捲的是**表格**，不是整頁：時間那一欄釘在左邊不動，其餘欄位左右拖。
  欄位一欄不減——能上下對齊比較，正是這些表存在的理由。
- 放得下的時候不出現橫向捲，表格填滿寬度。
- 沒有資料時顯示那句「沒有資料」，不出現一條空的捲動軸。

**策略積木工作台在手機上唯讀**

- 寬 768 以下看得到一條策略的條件長什麼樣，但拖不動、改不了，
  並在畫面上明說要改請用更寬的螢幕。
- 同一個寬度下，「新增策略」那個入口收起來並說明原因：
  讓人開了一張空白的工作台卻什麼都放不上去，比不讓他開更糟。
- 寬 768 起完整編輯照常。

**K 線圖表在手機上先讓出高度給圖**

- 寬 768 以下進入這一頁時，「看什麼」那塊一開始就是收起的，讓出的高度全部歸圖。
- 寬 768 起維持現況：一開始是展開的。
- **圖現在怎麼了**（連不上後端、取行情中、即時更新停了）不跟著被收走。
  收起的是控制項，不是圖的狀態。

**行情助手在手機上蓋滿畫面**

- 寬 768 以下叫出助手時它蓋滿整個畫面，帶一顆關閉鍵；「拖寬」這個動作在這裡不存在，
  那本來就是滑鼠的動作。
- 寬 768 起回到側邊那個可拖寬的抽屜。
- 對話那一頁在寬 768 以下只看到對話本身，歷史清單由一顆鍵叫出、選完就收。

**對話框不會被螢幕切掉**

- 最窄的寬度下，對話框跟著螢幕寬，左右各留一點邊，沒有任何一邊被切掉。
- 內容比螢幕高時在對話框裡自己捲，而「儲存 / 取消」永遠看得到。
- 手機橫放（高度只剩約 390）時同樣成立。

**最窄寬度下沒有一頁需要左右拖**

- 寬 390 逐一走過每一個畫面，整體都不需要左右拖動。
- 資料表與 K 線圖在自己的框裡橫向捲是刻意的，不算在內。

## Out of Scope

- **觸控專屬的新手勢**：積木工作台在手機上是唯讀的，因此不做「先點零件、再點格子」那種兩步操作。
- **任何業務規則、資料流與對後端的往來**一個字都沒有變。這個切片只改「同一份資料在不同寬度上長什麼樣」。
- **與寬度無關的外觀議題**：淺色主題、使用者自選字級等等。
- **平板保留橫捲窄帶的變體**：已決定一路到 1024 都用抽屜。

## Open Decisions

Items the PRD author should resolve:

- 兩套疏密的實際數值，以及它們如何一次在全站生效——不該是每個畫面各寫一份，那正是現在這個問題的來源。
- 手機上唯讀的工作台要用哪一種方式表達「這裡改不了」：整片壓暗，或零件不再像可以按的樣子。
- 既有畫面中重複出現的版面片段（面板頭、工具列、表格框、對話框）是否在這次一併收成共用的一份。
- 有一處畫面目前是自己寫死螢幕寬度的條件，而不是走全站共用的那一套；順手改回來。
- 專案總覽文件目前把「行動裝置專屬版面」列為不做的事，需一併更新。

## Context / Background

**已經有的東西**（不必重做，這次是把它用起來）：

- 全站的顏色、間距、字級、圓角、陰影已經集中在單一來源，畫面一律透過它取值，
  並且有自動檢查在擋「直接寫死一個顏色或距離」。
- 四段螢幕寬度（480 / 768 / 1024 / 1280）與取用它們的共用方式早就定義好了。
- 畫面已依粒度分成四層（最小的通用元件 → 功能單位 → 整塊區域 → 版面骨架）。

**真正缺的是把它用上**：全站四千六百多行畫面樣式裡，只有五個地方用過那套螢幕寬度機制。
外框本身已經有一版窄螢幕的安排（側欄躺平成頂上一條），這次會被抽屜取代。

**確認過的取捨**：

- 導覽一路到 1024 都用抽屜，不為平板另做第三種樣子——九個去處在那個寬度也塞不滿一條而不捲。
- 資料表選橫向捲而不是「一列變一張卡片」：一整欄數字要能上下比較，是這些表存在的理由，
  拆成卡片就沒了。
- 積木工作台選唯讀而不是整個擋掉：在手機上「查一下我派出去的策略長什麼樣」是真實的用途，
  而「在手機上組一條策略」不是。
