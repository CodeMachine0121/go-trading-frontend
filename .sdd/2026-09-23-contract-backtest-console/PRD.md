# Product Requirements Document (PRD)

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh

---

## 1. Background & Goal

- **Problem Statement:** 交易服務已能在逐倉合約帳戶上重演一支合約策略腳本或一份合約交易策略，交易策略也說得出吃哪一種行情；
  操作台卻還寫著「合約的回測還沒開放」，交易策略只能用現貨策略腳本拼、只能做現貨重演。
- **Expected Outcome:**
  - 合約策略腳本畫面有「回測」去處，可設定槓桿、交易模式、滑點，以及與現貨相同的每一格。
  - 合約成績單與交易明細說得出強平、資金費用、做多做空各自的表現、被擋下的開倉、維持保證金依據。
  - 交易策略可選行情種類（新拼時；存過後唯讀），合約交易策略可選交易模式，並能以合約帳戶規則重演。
  - 策略機器人只挑得到 K 線交易策略。現貨的每一個畫面行為不變。
- **Out of Scope:** 合約的策略機器人；全倉；四棵條件樹；信號來源混用兩種行情；在圖表上畫進出場；回測結果留存。

---

## 2. User Personas

- **Primary Role:** 使用操作台的交易者（策略腳本與交易策略的擁有者），多半在桌機、也會用手機看成績單。
- **Usage Context:** 寫好合約策略腳本或拼好合約交易策略後，換不同槓桿、停損與成本反覆重演，比較成績單。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 在合約策略腳本畫面回測 [P0]

**As a** 交易者, **I want** 在合約策略腳本畫面直接回測, **so that** 不必回去開 Postman。

```gherkin
Scenario: 合約策略腳本畫面有回測去處
  Given 打開合約策略腳本畫面
  When 看右欄頂上
  Then 有「指標預覽」與「回測」兩個去處

Scenario: 送出一次合約重演
  Given 在回測選了合約 BTCUSDT、槓桿 5、交易模式只做多
  When 按執行回測
  Then 送出的是一次合約重演，槓桿 5、交易模式只做多

Scenario: 槓桿與滑點留白
  Given 槓桿與滑點都留白
  When 按執行回測
  Then 送出的合約重演不帶槓桿與滑點（交易服務當作一倍、不計滑點）

Scenario: 槓桿小於一
  Given 槓桿填 0.5
  When 按執行回測
  Then 不送出，槓桿那一格旁邊寫「槓桿倍數不得小於 1 倍」

Scenario: 滑點為負
  Given 滑點填 -1
  When 按執行回測
  Then 不送出，滑點那一格旁邊寫「滑點不得為負」

Scenario: 交易服務指名槓桿那一格
  Given 交易服務以「這個合約標的最高只能開 125 倍槓桿」拒絕並指名槓桿
  When 按執行回測
  Then 那句話出現在槓桿那一格旁邊

Scenario: 現貨策略腳本的回測照舊
  Given 打開現貨策略腳本畫面的回測
  When 看回測條件
  Then 沒有槓桿、交易模式、滑點三格，仍是那句「只做現貨」的說明
```

### US-02 — 讀懂合約成績單與交易明細 [P0]

**As a** 交易者, **I want** 成績單說出合約帳戶才有的事, **so that** 分得出是強平、資金費用還是哪一邊在賠。

```gherkin
Scenario: 強平
  Given 一次合約重演有一筆被強平
  When 看成績單與交易明細
  Then 成績單寫強平出場 1 筆
  And 那一筆的出場原因寫「強平」

Scenario: 淨付出資金費用
  Given 累計資金費用是 18
  When 看成績單
  Then 資金費用那一格寫「付出 18.00」

Scenario: 淨收到資金費用
  Given 累計資金費用是 -5
  When 看成績單
  Then 資金費用那一格寫「收到 5.00」

Scenario: 沒有空單
  Given 一筆空單都沒有
  When 看成績單
  Then 做空 0 筆，做空勝率寫「不適用」

Scenario: 完整分級
  Given 維持保證金依據是完整分級，確認於 2026-09-01
  When 看成績單
  Then 維持保證金依據寫「完整分級」與確認日期，並說明用的是今天那一組分級

Scenario: 最小那一級
  Given 維持保證金依據是最小那一級
  When 看成績單
  Then 寫「最小那一級」，並說明大部位的強平價會被算得太遠

Scenario: 合約的交易明細
  Given 一筆 5 倍、數量 500、保證金 10000、資金費用 5 的空單
  When 看交易明細
  Then 那一筆寫做空、5 倍、數量 500、保證金 10000.00、資金費用 5.00

Scenario: 現貨成績單照舊
  Given 一次現貨重演
  When 看成績單與交易明細
  Then 沒有任何合約那幾格
```

### US-03 — 交易策略的行情種類與交易模式 [P0]

**As a** 交易者, **I want** 拼交易策略時選它吃的行情, **so that** 我拼得出合約交易策略。

```gherkin
Scenario: 合約交易策略只挑得到合約策略腳本
  Given 新拼一份交易策略，選合約行情
  When 加一個信號來源
  Then 挑得到的只有合約行情種類的策略腳本

Scenario: 沒選就是 K 線
  Given 新拼一份交易策略，沒動行情種類
  When 加一個信號來源
  Then 行情種類是 K 線，挑得到的只有 K 線策略腳本

Scenario: 換行情種類拿掉既有來源
  Given 新拼一份、已加兩個 K 線來源
  When 把行情種類改成合約行情
  Then 兩個來源被拿掉，並寫出「換了行情種類，原本的信號來源吃的是另一種行情，已經拿掉」

Scenario: 合約交易策略選交易模式
  Given 一份合約交易策略
  When 選只做空並存起來
  Then 存下的交易模式是只做空

Scenario: 已存的 K 線交易策略
  Given 一份已存的 K 線交易策略
  When 打開它
  Then 行情種類寫「K 線」且改不了，沒有交易模式那一格

Scenario: 清單標出行情種類
  Given 清單裡有一份合約的、一份 K 線的
  When 看交易策略清單
  Then 每一份標出它吃的是「合約行情」或「K 線」
```

### US-04 — 重演一份合約交易策略 [P0]

**As a** 交易者, **I want** 以合約帳戶規則重演合約交易策略, **so that** 派它上場前知道成績。

```gherkin
Scenario: 合約交易策略的回測條件
  Given 一份只做多的合約交易策略
  When 打開它的回測
  Then 標的從合約標的清單挑，有槓桿與滑點
  And 交易模式寫「只做多（由這份交易策略決定）」

Scenario: 送出合約交易策略重演
  Given 同上，槓桿 3
  When 按執行回測
  Then 送出的是合約交易策略重演，槓桿 3，不帶交易模式

Scenario: K 線交易策略的回測照舊
  Given 一份 K 線交易策略
  When 打開它的回測
  Then 回測條件與這一刀之前一模一樣
```

### US-05 — 機器人只挑得到 K 線交易策略 [P1]

```gherkin
Scenario: 機器人挑交易策略
  Given 我有一份合約交易策略與一份 K 線交易策略
  When 建一台機器人挑交易策略
  Then 只挑得到 K 線那一份
```

## 4. Business Flow & Logic

- **合約回測條件**＝現貨回測條件（期間、初始資金、押多少、出場價位、交易成本）＋槓桿、滑點，
  重演一支合約策略腳本時另加交易模式。送出前就地把關：槓桿留白或大於等於一；滑點留白或介於 0 到 100；
  交易模式三選一。留白的兩格不上線。
- **合約的說明**：逐倉、強平看標記價格、資金費率一律計入、數量照交易規格取整、一格內的順序
  （先收付資金費用 → 止損與強平誰近誰先 → 止盈 → 信號）。
- **資金費用的說法**：正是付出、負是收到、零寫零。
- **換行情種類**只在還沒存過時可以；換了就清空信號來源並說一聲。
- **Edge Cases**：交易服務指名的欄位落在該欄位旁邊；認不得的欄位落成籠統的「請求的問題」。

---

## 5. UI/UX Design & Interaction

- 沿用既有回測條件、成績單、交易明細三塊的版面；合約那幾格「有才出現」。
- 交易模式用下拉選單，每一個選項附一句說明；合約交易策略的回測條件把交易模式寫成唯讀一句話。
- 行情種類在交易策略工作台的名稱旁；已存過的那一份是唯讀標記。

---

## 6. Non-Functional Requirements

- 手機寬度下合約多出的欄位照樣折行，不橫向捲動。
- 金額一律精確小數；槓桿、數量照後端給的精確數字呈現。

---

## 7. Dependencies & Risks

- 依賴交易服務的合約回測兩個入口與交易策略的行情種類、交易模式兩欄。
- 風險：舊版後端不回合約那幾格時，一律當作現貨成績單呈現。
