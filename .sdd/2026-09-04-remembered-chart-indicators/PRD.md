## 1. Background & Goal

### 問題

圖表記得住兩件小事——**一條線是什麼顏色**、**這支策略的這個旋鈕上次調成什麼**——
但它不記得**圖上擺了哪幾支**。

於是每天坐下來的第一件事都一樣：挑均線、期數 20、加入；挑均線、期數 60、加入；
挑布林、倍數 2、加入。九個動作，而它們每一天都一模一樣。

上一個切片把「不留存清單」寫成明確不做，理由是「每次坐下來想看的東西都不同」。
用了一段時間之後這句話被證明說反了：想看的**個股**每次都不同，
想看的**指標**每次都一樣——那是一套看法，不是一次查詢。

### 目標

**圖上擺著的那幾支指標留存下來**：重新打開畫面時，同樣的那幾支依同樣的順序回到清單上，
帶著**各自的值**，並各自算一次。

### 成功的樣子

- 看行情的人打開畫面，**他那套指標已經在圖上了**——一個動作都不必做。
- 同一支均線的 20 期與 60 期**兩筆都回來**，不是回來兩條 60 期。

### 明確不做

- **依交易標的分別留存**：留存的是一套，跨每一檔通用。
- **留存交易標的、彙總刻度、看哪一段**：重新打開畫面時它們仍然是預設的那些。
- **留存好幾套並在它們之間切換**（版面／工作區）。
- **把留存搬到後端**，讓另一台機器也看得到同一套。
- 在圖表上編輯策略的**旋鈕宣告**；旋鈕的**型別系統**。

## 3. User Stories & Acceptance Criteria

### US-01 — 上次那幾支自己回到圖上 [priority: P0]

**As a** 看行情的人，**I want** 重新打開畫面時上次擺著的那幾支指標自己回到圖上，
**so that** 我不必每天重複同樣的九個動作。

```gherkin
Scenario: 一筆回來
  Given 圖上擺著「均線」，期數 20
  When 重新打開畫面
  Then 清單上有那一筆
  And 圖上有它那一條線

Scenario: 好幾筆依原來的順序回來
  Given 圖上依序擺著「均線」與「布林」
  When 重新打開畫面
  Then 兩筆依同樣的順序回到清單上

Scenario: 同一支的兩筆各自帶著自己的值回來
  Given 圖上擺著同一支均線兩筆，期數分別是 20 與 60
  When 重新打開畫面
  Then 清單上有兩筆
  And 一筆的期數是 20，另一筆是 60
  And 兩筆各自用自己的值算了一次

Scenario: 移除過的那一筆不回來
  Given 圖上擺著兩筆
  And 移除其中一筆
  When 重新打開畫面
  Then 只有剩下的那一筆回來

Scenario: 改過的值就是回來時的值
  Given 圖上擺著「均線」，期數被改成 60
  When 重新打開畫面
  Then 那一筆回來，期數是 60

Scenario: 一支都沒擺過時清單是空的
  Given 圖上一支指標都沒有
  When 重新打開畫面
  Then 清單是空的

Scenario: 還在調旋鈕、還沒加入的那一筆不算擺過
  Given 挑了一支有旋鈕的策略，那幾格還在調
  And 還沒按下加入
  When 重新打開畫面
  Then 清單是空的
```

### US-02 — 什麼時候寫下來 [priority: P0]

**As a** 看行情的人，**I want** 我對清單做的每一個改動立刻被記下來，
**so that** 我不必為了「讓它記住」而多做任何動作。

```gherkin
Scenario: 加入一筆就寫下來
  Given 圖上一支指標都沒有
  When 套用一支策略
  Then 留存的內容是那一筆

Scenario: 移除一筆就寫下來
  Given 圖上擺著兩筆
  When 移除其中一筆
  Then 留存的內容只有剩下的那一筆

Scenario: 改一筆的值就寫下來
  Given 圖上擺著「均線」，期數 20
  When 把期數改成 60
  Then 留存的內容是期數 60

Scenario: 值填得用不了的時候不寫
  Given 圖上擺著「均線」，期數 20
  When 把期數改成 0
  Then 留存的內容仍然是期數 20
  And 畫面上那一格顯示的是使用者剛剛打的 0
```

### US-03 — 這台瀏覽器不讓存東西時 [priority: P0]

**As a** 看行情的人，**I want** 在無痕視窗或封鎖網站資料的瀏覽器裡照樣用得動圖表，
**so that** 一個記憶功能不會把主功能弄壞。

```gherkin
Scenario: 寫不進去不影響這一次
  Given 這台瀏覽器不讓網站存東西
  When 套用一支策略
  Then 它照樣上圖並算了一次
  And 畫面上沒有出現任何錯誤

Scenario: 讀不出來就當成沒擺過
  Given 這台瀏覽器不讓網站存東西
  When 重新打開畫面
  Then 清單是空的
  And 圖表本身照常顯示
```

### US-04 — 策略在這段時間裡被改過 [priority: P0]

**As a** 看行情的人，**I want** 留存的那幾筆對得上策略現在的樣子，
**so that** 圖上不會出現一筆我現在根本加不進來、或者算不出來的東西。

```gherkin
Scenario: 策略被刪掉的那一筆不回來
  Given 留存著兩筆
  And 其中一筆的策略已經被刪除
  When 重新打開畫面
  Then 只有另一筆回來
  And 畫面上沒有出現任何錯誤

Scenario: 現在畫不成線的那一筆不回來
  Given 留存著一筆
  And 那支策略現在畫不成線
  When 重新打開畫面
  Then 那一筆不回來

Scenario: 策略多宣告一個旋鈕時，新的那一格用它的預設值
  Given 留存著「期數 60」
  And 那支策略現在多宣告了「倍數」，預設值是 2
  When 重新打開畫面
  Then 期數是 60
  And 倍數是 2

Scenario: 策略不再宣告某個旋鈕時，留存的值整個消失
  Given 留存著「期數 60」
  And 那支策略現在不再宣告「期數」
  When 重新打開畫面
  Then 沒有期數那一格
  And 那個 60 不參與計算

Scenario: 旋鈕被改名時，舊值丟掉、新名字用預設值
  Given 留存著「期數 60」
  And 那個旋鈕被改名成「週期」，預設值是 20
  When 重新打開畫面
  Then 只有「週期」一格，值是 20

Scenario: 策略改名時用現在的名字
  Given 留存著一筆
  And 那支策略被改了名字
  When 重新打開畫面
  Then 那一筆顯示的是現在的名字
```

### US-05 — 留存的東西壞掉時 [priority: P1]

**As a** 看行情的人，**I want** 留存的內容壞掉時圖表照樣打得開，
**so that** 我不會因為瀏覽器裡一份讀不出來的東西而失去整張圖。

```gherkin
Scenario: 整份讀不出來就當成沒擺過
  Given 留存的內容不是一份讀得出來的清單
  When 重新打開畫面
  Then 清單是空的
  And 畫面上沒有出現任何錯誤

Scenario: 其中一筆讀不出來就跳過那一筆
  Given 留存著兩筆
  And 其中一筆沒有策略識別碼
  When 重新打開畫面
  Then 只有另一筆回來

Scenario: 某一格的值用不了時退回策略的預設值
  Given 留存著「期數 0」
  And 期數宣告成回看根數，預設值是 20
  When 重新打開畫面
  Then 那一格是 20
  And 那一筆照樣回到圖上
```

### US-06 — 既有的兩種記憶不變 [priority: P0]

**As a** 看行情的人，**I want** 顏色與旋鈕習慣值照舊記得住，
**so that** 新的留存不會把已經好用的東西換掉。

```gherkin
Scenario: 回來的那一筆用挑過的顏色
  Given 替某支策略的線挑過藍色
  And 圖上擺著那一支
  When 重新打開畫面
  Then 那條線是藍色

Scenario: 挑一支新的仍然帶上次調過的值
  Given 上次把某支策略的期數調成 60
  And 圖上現在沒有那一支
  When 重新打開畫面後挑那一支
  Then 那一格是 60
```

## 4. Business Flow & Logic

### 主流程

```
打開畫面
  ├─ 取行情 ─────────────────┐
  └─ 取策略清單 ─────────────┤   （兩件事各自進行，誰先回來都可以）
                             │
     取到策略清單之後：       │
     讀留存的那幾筆           │
       ├─ 讀不出來 → 空的     │
       └─ 逐筆對照策略清單：   │
            ├─ 找不到那支策略 → 跳過
            ├─ 那支現在畫不成線 → 跳過
            └─ 對得上 → 依宣告重建那幾格（留存的值優先，用不了或沒有就用預設值）
                          └─ 進清單，並在「算哪一段」可用時算一次
                             （行情還沒回來時先不算，等它回來一起算）

之後每一次清單改動（加入／移除／改值）
  └─ 值用得了 → 立刻把整份清單寫下來
     值用不了 → 畫面留著使用者打的東西，但不寫
```

### 核心商業規則

| 規則 | 說明 |
| :--- | :--- |
| **留存的是每一筆各自的值** | 不是「這支策略上次調成什麼」——後者記不住同一支的兩筆 |
| **宣告是唯一的真相** | 名稱與種類一律照策略現在的宣告；留存裡有、宣告裡沒有的名字丟掉 |
| **留存的值要用得了才採用** | 對它宣告的種類用不了（如回看根數 0）就退回策略的預設值 |
| **挑不到的那幾支不回來** | 策略已刪除、或現在畫不成線 → 那一筆不回來 |
| **順序照留存的順序** | 順序決定沒挑過顏色時誰先拿到哪個顏色 |
| **用不了的值不寫** | 畫面顯示使用者打的東西，留存的必須是能用的那一份 |
| **還沒上圖的不留存** | 正在調旋鈕的那一筆從來沒有上過圖 |

## 5. UI/UX

**畫面上沒有任何新元件、沒有任何新按鈕。** 這個功能的樣子就是「打開畫面時那幾筆已經在了」。

| 情境 | 使用者看到 |
| :--- | :--- |
| 留存著三筆 | 清單上三列，各自照常顯示「正在算／算出哪幾條線／算不出來的原因」 |
| 留存著三筆，其中一筆的策略被刪了 | 清單上兩列，**沒有任何說明**——那一筆對他來說已經不存在了 |
| 一筆都沒留存、或讀不出來 | 與這個功能出現之前一模一樣：清單是空的 |

**刻意不做的呈現**：不告訴使用者「有一筆因為策略被刪掉而沒有回來」。
他刪掉那支策略時就知道自己刪了什麼，而一則講著他上個月的操作的說明只會擋在畫面上。

## 6. Non-Functional Requirements

| 項目 | 要求 |
| :--- | :--- |
| **不擋主功能** | 讀／寫留存失敗一律不影響圖表：讀不到當成沒擺過，寫不進去只影響下次 |
| **不多打一趟後端** | 還原不需要額外的請求——策略清單本來就會取，行情本來就會取 |
| **還原後只算一次** | 每一筆各算一次；不因為「還原」與「第一次擺好位置」而算兩遍 |
| **順序穩定** | 還原的順序等於留存的順序，因此顏色的分配也穩定 |

## 7. Dependencies & Risks

### Dependencies

| 依賴 | 為什麼 |
| :--- | :--- |
| `.sdd/2026-09-04-chart-indicator-parameters/` | 「一次套用」的身分、每一筆各自的值、宣告是唯一的真相，全部沿用 |
| `.sdd/2026-09-03-chart-indicator-overlay/` | 清單、失敗說明、線色、重算的既有規則 |
| `GET /strategies` | 還原要靠它把識別碼對回一支現在的策略 |
| 瀏覽器儲存 | 唯一的留存位置；不讓存東西時整個功能安靜地不生效 |

### Known Risks

| 風險 | 影響 | 對策 |
| :--- | :--- | :--- |
| **行情與策略清單誰先回來不確定** | 策略先回來時「算哪一段」還不存在，那幾筆會**安靜地不算**——清單上有列、圖上沒有線 | 還原時算不了就先不算，等第一次擺好位置時一起算；那一刻不套用「等停手」的節流（它不是拖動） |
| **用留存的清單去推「這支上次調成什麼」** | 同一支的兩筆會變成兩條同值的線，且不報錯 | 兩種記憶各自留著，各自回答自己的問題 |
| **留存裡混進用不了的值** | 那一筆帶著算不出來的值回到圖上 | 用不了就退回策略的預設值；寫的時候本來就不寫用不了的值 |
| **把種類也留存下來** | 過期的種類會贏過宣告——後端曾經踩過同一個坑 | 只留存名稱與值，種類一律照宣告 |
