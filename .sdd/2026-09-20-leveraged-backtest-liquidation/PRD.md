# Product Requirements Document — 回測表單的槓桿與成績單的強平

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal

### Problem Statement

重演那張表單問得出六件關於「這一次怎麼操作」的事，獨獨問不出一件：**借多少錢**。

於是一個真的會開槓桿的人，只能填一個他不會用的設定，拿一張描述別人帳戶的成績單回去。
而那張成績單錯得特別危險：賺賠差了槓桿倍數那麼多（這個看得出來），
而且**他會在中途被強制出場而成績單完全不知道**（這個看不出來）——
帳戶早就歸零，後面那幾十筆交易根本不存在，報酬率照樣把它們算進去。

後端已經做完了。現在只有畫面問不出來、也說不出來。

### Expected Outcome

- 兩張重演表單都多一組**槓桿**（槓桿倍數＋維持保證金率）。
- 填了講不通的值**當場說**，訊息落在那一組旁邊。
- 成績單多一格**強平出場**，交易明細的出場原因說得出**強平**。
- **整組留白時，這張畫面送出去的請求與這一刀之前逐字相同。**

### Out of Scope

- 資金費率、把強制平倉價畫出來、資金曲線標出被打掉的那一棒。
- 機器人那張表單的槓桿倍數：它早就有了，這一刀只讓它與回測共用同一句拒絕的話，不改行為。

---

## 2. User Personas

- **Primary:** 自己寫策略、會開永續合約的人。坐在畫面前一次一次調：換標的、換期間、
  換停損、**換槓桿**，比較成績單。
- **Usage Context:** 手機與桌機都用（這個專案是 mobile-first）。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 表單問得出槓桿 [P0]

**As a** 會開槓桿的使用者，**I want** 在重演表單上說出要開幾倍，
**so that** 成績單算的是我實際會開的那種倉。

```gherkin
Scenario: 填了槓桿就送得出去
  Given 重演表單上槓桿倍數填 5
  When 送出
  Then 請求帶著槓桿倍數 5

Scenario: 整組留白時那兩格根本不出現在請求裡
  Given 重演表單上槓桿那一組兩格都留白
  When 送出
  Then 請求裡沒有槓桿倍數這一格
  And 請求裡沒有維持保證金率這一格

Scenario: 填一倍也當作不借錢
  Given 重演表單上槓桿倍數填 1
  When 送出
  Then 請求裡沒有槓桿倍數這一格

Scenario: 只填維持保證金率也照樣送得出去
  Given 重演表單上槓桿倍數留白、維持保證金率填 25
  When 送出
  Then 請求成功送出
  And 請求裡沒有槓桿倍數這一格

Scenario: 重演一份交易策略也問得到槓桿
  Given 重演一份交易策略的表單上槓桿倍數填 5
  When 送出
  Then 請求帶著槓桿倍數 5

Scenario: 那一組旁邊說得出留白是什麼意思
  Given 打開重演表單
  When 看槓桿那一組
  Then 旁邊寫著留白就不借錢，以及維持保證金率留白時用 0.5%
```

### US-02 — 講不通的值當場擋下來 [P0]

**As a** 使用者，**I want** 填錯時立刻在那一格旁邊看到為什麼，
**so that** 我不用把一次注定被拒絕的請求送出去再等回來。

```gherkin
Scenario: 槓桿倍數小於一
  Given 重演表單上槓桿倍數填 0.5
  When 送出
  Then 請求沒有送出
  And 槓桿那一組旁邊出現「槓桿倍數不得小於 1 倍」

Scenario: 槓桿倍數不是一個數字
  Given 重演表單上槓桿倍數填 abc
  When 送出
  Then 請求沒有送出
  And 槓桿那一組旁邊出現「槓桿倍數請填一個數字」

Scenario: 維持保證金率為負
  Given 重演表單上維持保證金率填 -1
  When 送出
  Then 請求沒有送出
  And 槓桿那一組旁邊說維持保證金率不得為負

Scenario: 維持保證金率大到那一注開倉當下就撐不住
  Given 重演表單上槓桿倍數填 5、維持保證金率填 25
  When 送出
  Then 請求沒有送出
  And 槓桿那一組旁邊說出 5 倍下維持保證金率最多能填到多少

Scenario: 剛好還開得成
  Given 重演表單上槓桿倍數填 5、維持保證金率填 19
  When 送出
  Then 請求成功送出

Scenario: 沒有借錢時維持保證金率怎麼填都不擋
  Given 重演表單上槓桿倍數留白、維持保證金率填 999
  When 送出
  Then 請求成功送出
```

### US-03 — 現貨開不了槓桿 [P0]

**As a** 使用者，**I want** 現貨配槓桿這種說不通的組合被擋下來，
**so that** 我不會拿到一張照著我做不到的操作算出來的成績單。

```gherkin
Scenario: 同一張表單上就看得到交易模式，所以當場擋
  Given 重演一支策略腳本，交易模式挑現貨、槓桿倍數填 3
  When 送出
  Then 請求沒有送出
  And 槓桿那一組旁邊說現貨開不了槓桿

Scenario: 現貨不填槓桿照常
  Given 重演一支策略腳本，交易模式挑現貨、槓桿那一組留白
  When 送出
  Then 請求成功送出

Scenario: 看不到交易模式的那張表單交給後端回答
  Given 重演一份交易策略，那一份記著現貨，槓桿倍數填 3
  When 送出，而後端指著槓桿那一格拒絕
  Then 槓桿那一組旁邊出現後端說的那句話
```

### US-04 — 成績單看得出爆倉 [P0]

**As a** 使用者，**I want** 成績單講出這個帳戶歸零過幾次，
**so that** 我分得出「停損一直在擋」與「押到歸零過三次」這兩張長得很像的成績單。

```gherkin
Scenario: 有強平就顯示
  Given 一次重演有兩筆被強制平倉
  When 看成績單
  Then 出現強平出場 2

Scenario: 沒有強平就不佔位置
  Given 一次重演一筆都沒被強制平倉
  When 看成績單
  Then 成績單上沒有強平出場那一格

Scenario: 交易明細指得出是哪一筆
  Given 某一筆的出場原因是強制平倉
  When 看交易明細
  Then 那一列的出場原因寫著強平

Scenario: 舊版後端不說這件事也不會壞
  Given 後端回來的成績單沒有強平出場筆數這一項
  When 看成績單
  Then 沒有強平出場那一格
  And 其餘每一格照舊
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 整組留白＝不借錢。** 槓桿倍數留白、填 0 或填 1，一律不借錢；
那兩格**不出現在請求裡**（不是送 0）。送 0 雖然等價，但那個等價是巧合：
空輸入框轉成的 0 是解析的結果，不是使用者的意思。與出場價位、交易成本同一條規則。

**R2 — 這一組兩格的留白規則不一樣。** 槓桿倍數留白＝關掉整組；
維持保證金率留白＝用 0.5%。這是它與隔壁兩組最大的差別，提示要說出來。

**R3 — 上限是算出來的。** 維持保證金率必須小於 `100 ÷ 槓桿倍數`，
拒絕時要說出那個數字。

**R4 — 拒絕指向一組。** 一則訊息蓋住兩格，句子本身說是哪一格。

**R5 — 「槓桿倍數不得小於 1 倍」只有一份。** 機器人那張表單問同樣的東西，
同一個 0.5 在兩張表單上必須得到同一句話。

**R6 — 現貨的檢查只做得到它看得見的地方。** 重演一支策略腳本時交易模式在同一張表單上，
當場擋；重演一份交易策略時它在那一份身上，畫面看不到，交給後端。

**R7 — 逐字相容。** 整組留白時，這張畫面送出去的請求與這一組出現之前逐字相同。

### Edge Cases

| 情況 | 行為 |
| :--- | :--- |
| 兩格都留白 | 兩格都不進請求 |
| 槓桿填 1 | 不進請求（不借錢） |
| 只填維持保證金率 | 只有它不進請求（沒有借錢就不需要） |
| 填了非數字 | 當場擋，說請填一個數字 |
| 後端沒有強平筆數這一項 | 當作零，那一格不顯示 |
| 後端回一個認不得的出場原因 | 沿用既有處理（當訊號出場） |

## 5. UI/UX Design & Interaction

- 槓桿是**一組兩格併排**，整組佔滿一列，長相與出場價位、交易成本一模一樣——
  三組都是「一個概念、兩個數字、留白有意思」，掃過去要認得出是同一種東西。
- 那一組的**提示**要說兩件事：留白就不借錢、維持保證金率留白時是 0.5%。
- **順序擺在交易成本之後**：一個人先決定押多少、能忍多少、付多少，最後才決定借多少。
- 成績單的**強平出場**擺在止損出場、止盈出場之後，**大於零才出現**。
- 手機寬度下兩格自己折成上下兩格，仍然同時看得見（沿用既有的併排排版）。

---

## 6. Non-Functional Requirements

- **相容性（最重要）：** 整組留白時送出去的請求與這一刀之前逐字相同。
- **精確度：** 兩格都是精確小數，不經過浮點數。
- **型別：** 不出現 `any`。
- **樣式：** 沿用既有的併排排版類別，不新增第二份。

---

## 7. Dependencies & Risks

### Dependencies

- 後端的兩支重演端點已經收得下這兩格，成績單已經有強平出場筆數，出場原因已經多一種。
- 既有的 `ExitDistanceDomain` / `TransactionCostRateDomain` 兩個共用驗證模型的形狀，
  新的驗證模型比照它們。

### Risks

| 風險 | 緩解 |
| :--- | :--- |
| 留白被送成 0，把舊請求改掉 | 「留白的不上線」有專屬驗收情境（US-01 第二、三、四則） |
| 兩張表單漂移 | 兩張表單共用同一個分子元件；兩邊各一個驗收情境 |
| 「不得小於 1 倍」長出第二份 | 抽成共用模型，機器人那個模型改成委派它 |
| 現貨檢查做在做不到的地方 | US-03 三則各自說明哪一張表單做得到什麼 |
