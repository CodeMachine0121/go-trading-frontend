## 1. Background & Goal (Why & Goal)

### Problem Statement

這台操作台的**指路**與**說法**各自累積了一層漂移，而兩層都長在同一個地方。

**指路。** 側欄上有九個去處，其中一個（觀察清單）做的是一件一次性的設定，
它卻佔著窄螢幕底部四格中的一格——那是全站最貴的四個位置。
而真正每天要進去的「交易策略」根本不在那張表上：它只有兩條路走得到——
機器人清單標頭那顆按鈕，或者自己打網址。使用者因此**以為交易策略是機器人的一部分**，
但它不是：一份交易策略可以被好幾台機器人引用，它比任何一台活得久。

**說法。** 畫面上有四組詞與後端那份通用語言對不起來：

| 畫面上 | 後端 | 後果 |
|---|---|---|
| 指標計算 | 策略腳本 | 那一頁上有兩個去處、一個腳本庫、一個市集入口、一整套參數宣告——指標計算只是它能做的其中一件事，卻當了整頁的名字 |
| 信號來源 | 訊號來源 | 這一側的 UL-MAP 自己寫的就是「訊號來源」，畫面違反自己的地圖 |
| 重演中… | 回測中… | 同一顆按鈕閒著時說「執行回測」、跑起來說「重演中」，像兩件事 |
| 策略腳本市集 | `Marketplace` | 與助手同一件事：那是一個**去處**，而去處在這一版一律給英文名字。它還與自己的策略腳本庫共用同一顆清單圖示，而那是兩件事 |
| 止損⇄停損 走錯房間 | 回測用止損、部位規劃用停損 | 這是兩件真的不同的事（一個從進場價量起、一個從最新價量起），畫面把它們合成了一件 |

**還有那顆鍵。** 浮在右下角叫出助手的是一顆圓的機器人頭，
而側欄上緊鄰的另一個去處（策略機器人）真的就是一台機器——兩者共用同一顆頭，
差別只有一圈環，而那一圈在 16 像素下看不出來。

### Expected Outcome

側欄與底部那一排指向現在真正要去的地方；畫面上的每一個名字都在後端那份地圖上；
助手與市集各有一個叫得出口的名字（`AI-Assistant`、`Marketplace`），
以及一個不會與隔壁那一格搞混的記號。

### Out of Scope

| 不做 | 為什麼 |
|:---|:---|
| 動後端任何端點 | 觀察清單與 `/indicator-calculations` 端點都還在，拿掉的只是這一側到得了它的路 |
| 把 `IndicatorCalculationApplication` 那一串型別改名 | 「執行指標計算」在後端仍然是有效的業務動作。改的是畫面叫什麼 |
| 把「每根涵蓋」改回「彙總刻度」 | 那是這一側刻意記在自己 UL-MAP 上的說法，不是漂移 |
| 把句子裡的「重演」全部清掉 | 解釋一次回測在做什麼時，「重演一遍」是解釋不是名字 |
| 把句子裡的「助手」改成 `AI-Assistant` | 後端那個角色就叫助手；`AI-Assistant` 是這個**去處**的名字 |
| 改交易策略那一頁的內容 | 它已經是完整的一頁，這一刀只替它在側欄開一格 |
| 改助手與市集的任何行為 | 只換名字、圖示與那顆鍵的長相 |
| 動 `library` 那顆圖示 | 它在策略腳本那一頁上還有工作（開自己的策略腳本庫那顆鍵） |

## 3. User Stories & Acceptance Criteria

### US-01 — 觀察清單整個不見了 [priority: P0]

> **作為** 操作台的唯一使用者
> **我想要** 觀察清單這個去處整個消失
> **以便** 底部那四格留給我每天真的會按的東西

**Acceptance Criteria**

- **AC-01.1** 側欄上沒有「觀察清單」。
- **AC-01.2** 底部那一排與「更多」那張紙上都沒有它。
- **AC-01.3** `/watchlist` 這條路由不存在。
- **AC-01.4** 它整條垂直切片一起走：頁面、`WatchlistPanel`、`WatchlistEntryForm`、
  `WatchlistApplication`、`WatchlistService`、`WatchlistProxy`、`IWatchlistProxy`、
  `WatchlistEntryDto`，以及它們的測試與組裝根上那一段。
- **AC-01.5** **`追蹤中` 留著**：挑交易標的時仍然看得出後端有沒有在抓這一檔。
  那是後端在交易標的上回的事實，不是觀察清單這一頁的東西。

```gherkin
Scenario: 側欄上不再有觀察清單
  Given 使用者在寬螢幕上打開任何一頁
  When 他讀側欄
  Then 他讀不到「觀察清單」

Scenario: 追蹤中那個標記還在
  Given 使用者在 K 線圖表上挑交易標的
  When 他看一檔後端正在抓的標的
  Then 他仍然看得出它是追蹤中
```

### US-02 — 交易策略是側欄上自己的一格 [priority: P0]

> **作為** 操作台的唯一使用者
> **我想要** 從側欄直接走進交易策略
> **以便** 我不必先進機器人那一頁才找得到我的規則

**Acceptance Criteria**

- **AC-02.1** 側欄上有「交易策略」，指向 `/trading-strategies`。
- **AC-02.2** 它**排在 `Marketplace` 與「策略機器人」之間**——
  那是「寫腳本 → 拼規則 → 派機器人」的中間那一步。
- **AC-02.3** 它的圖示與別人都不一樣，且不是機器人那一顆。
- **AC-02.4** 機器人清單標頭上那顆「我的交易策略」**拿掉**。
- **AC-02.5** 每一台機器人身上那條通往它引用的那一份的連結**留著**——
  那不是導覽，那是「這一台在用的是哪一份」。
- **AC-02.6** 機器人表單裡「一份都沒有，先去拼一份」那條路**留著**。

```gherkin
Scenario: 從側欄走進交易策略
  Given 使用者在寬螢幕上
  When 他點側欄上的「交易策略」
  Then 他走到 /trading-strategies

Scenario: 機器人清單不再是第二個入口
  Given 使用者在機器人清單上
  When 他讀那個面板的標頭
  Then 他讀不到「我的交易策略」那顆鍵
  And 他仍然看得到「＋ 拼一台機器人」
```

### US-04 — 訊號就叫訊號 [priority: P1]

> **作為** 操作台的唯一使用者
> **我想要** 畫面上講的是「訊號來源」
> **以便** 它與後端那份地圖上的那個詞是同一個

**Acceptance Criteria**

- **AC-04.1** 交易策略被拒絕時，那幾句話說「訊號來源」
  （至少要有一個、每一個都要有代號、代號不得重複、必須指名一支策略腳本）。
- **AC-04.2** 交易策略的重演表單上，彙總刻度那句唯讀說明說「訊號來源」；
  參數與算式出問題時那兩句指路也說「訊號來源」。
- **AC-04.3** 工作檯上「這支不吐訊號，當不了訊號來源」。
- **AC-04.4** 機器人清單上說「在訊號變了的時候傳訊息給你」。
- **AC-04.5** 回測規則那幾句說「訊號」。
- **AC-04.6** **例外只有一個**：指標值種類那個選項仍然叫「一個信號」——
  那是後端 UL-MAP 白紙黑字的選項名稱。

```gherkin
Scenario: 一份沒有來源的交易策略
  Given 使用者拼了一份沒有任何來源的交易策略
  When 他按下儲存
  Then 那句拒絕說「一份交易策略至少要有一個訊號來源」

Scenario: 指標值種類那個選項不跟著改
  Given 使用者在挑指標值種類
  Then 其中一個選項仍然叫「一個信號」
```

### US-05 — 止損與停損各自回到自己的房間 [priority: P1]

> **作為** 操作台的唯一使用者
> **我想要** 回測那邊講止損、機器人那邊講停損
> **以便** 我不會把「從進場價量起」與「從最新價量起」當成同一件事

**Acceptance Criteria**

- **AC-05.1** 回測那兩格被擋下時，那句話說「**止損距離**」「**止盈距離**」
  （兩張重演表單都是，因為它們共用同一段驗證）。
- **AC-05.2** 回測規則那幾句一律「止損／止盈」。
- **AC-05.3** 機器人表單部位規劃那句說明說「**停損與停利**」
  （那兩格的標籤本來就已經是停損距離／停利距離）。
- **AC-05.4** 機器人執行紀錄那一行建議部位說「**停損** X · **停利** Y」。

```gherkin
Scenario: 回測的止損距離填成負的
  Given 使用者在重演表單的止損那一格填 -1
  When 他按下執行回測
  Then 那句拒絕說的是「止損距離」

Scenario: 機器人建議的部位
  Given 一台機器人某一輪建議了部位
  When 使用者讀那一行
  Then 他讀到「押 … · 停損 … · 停利 …」
```

### US-06 — 回測跑起來還是叫回測 [priority: P2]

> **作為** 操作台的唯一使用者
> **我想要** 同一顆按鈕從頭到尾用同一個詞
> **以便** 我不會以為「執行回測」與「重演中」是兩件事

**Acceptance Criteria**

- **AC-06.2** 兩張表單進行中那句說明開頭是「回測中…」。
- **AC-06.3** 算完那一句寫「**回測了 N 根**」。
- **AC-06.4** 還沒存過的交易策略那句話說「還沒有東西可以拿去**回測**」。

> **作為** 操作台的唯一使用者

### US-08 — 那顆鍵換一個長相 [priority: P1]

> **作為** 操作台的唯一使用者
> **我想要** 那顆浮在畫面上的鍵好看一點
> **以便** 它看起來像介面的一部分，而不是有人把一顆球忘在畫面上

**Acceptance Criteria**

- **AC-08.1** 它是一枚**圓角方塊**（squircle），不再是圓的。
- **AC-08.2** 它帶一顆**四角星**與一行小字 `AI`。
- **AC-08.3** 它有漸層底與一圈柔光，停在上面時光暈變強。
- **AC-08.4** **大小仍然是外面給的那個數字**（64 像素）——
  夾回看得見的範圍那條規則讀的就是它，兩邊各寫一份會讓它靠邊時對不齊。
- **AC-08.5** **拖與按的行為一個字都不改**：拖到哪裡就停在哪裡、放下記住位置、
  拖過就不打開抽屜、單純按一下才打開。
- **AC-08.6** 那顆四角星同時是側欄那一格的圖示、抽屜標頭的記號，
  以及每一則回答旁邊的頭像。
- **AC-08.7** 原本那顆機器人頭沒有人用了，**從圖示表上刪掉**；
  策略機器人那一顆（外面有一圈環的）留著。

```gherkin
Scenario: 拖它
  Given 那枚晶片在右下角
  When 使用者把它拖到別的地方再放開
  Then 它停在那裡
  And 抽屜沒有打開

Scenario: 按它
  Given 那枚晶片在右下角
  When 使用者按一下就放開
  Then 抽屜打開
```

## 4. Business Rules

| # | 規則 |
|---|---|
| BR-01 | **一個去處只有一個入口。** 側欄上有了自己一格的東西，別的面板標頭就不再放通往它的按鈕。指向「某一筆特定資料」的連結不在此限 |
| BR-02 | **畫面上的名字一律出自後端 UL-MAP 的 User-Facing Label。** 這一側只在後端沒有對應詞時（畫面、輸入、呈現狀態）才自己取名，並記在自己的 UL-MAP 上 |
| BR-03 | **「信號」只留在指標值種類那個選項名稱上**（「一個信號」）。其餘一律「訊號」 |
| BR-04 | **止損／止盈只用在回測**（從進場價量起）；**停損／停利只用在部位規劃**（從最新價量起）。兩組詞不得互換 |
| BR-05 | **英文名字給去處，中文名字給那個東西。** `AI-Assistant` ⇄「助手」、`Marketplace` ⇄「市集」：標題、導覽、抽屜標頭、那顆鍵，以及**指向那個去處的路標**用前者；句子裡用後者 |
| BR-06 | **一個圖示只說一件事，兩個去處不共用一顆。** `library` 已經是「我自己的策略腳本庫」，所以 `Marketplace` 要自己的 `store`；`standing-bot` 已經是策略機器人，所以 `AI-Assistant` 要自己的 `sparkle` |
| BR-07 | **那顆鍵多大只有一個數字。** 它從外面傳進來，樣式照著畫；夾回範圍的算式讀的是同一個 |

## 5. Non-Functional Requirements

| 面向 | 要求 |
|:---|:---|
| 可及性 | 那顆鍵只有圖示與兩個字，所以無障礙名稱是必要的，不是裝飾；底部那一排每一格仍然按得到（`tap-target`） |
| 樣式 | 新的長相一律走 token：新增的柔光是 `_tokens.scss` 上的一筆陰影，不在元件裡寫任何字面值 |
| 版面 | `AI-Assistant` 這個名字在 390 寬的螢幕上，底部那一格仍然放得下（不換行、不裁切） |
| 相容 | 這一刀不碰後端契約，任何一個端點的請求與回應都不變 |
