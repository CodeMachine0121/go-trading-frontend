# Product Requirements Document (PRD)

**Feature:** 自動下單限價進場（網頁）
**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:**
  交易服務把合約機器人自動下單的開倉改成**有上限的限價進場**：限價＝參考價 ±「開倉容許滑價」，一個觸發間隔內沒全部成交就撤掉剩下的。
  這個設定每台機器人一個，操作台卻沒有地方設；執行紀錄上看不到參考價、限價、成交多少、滑價多少，也分不出「等待成交」「沒有成交」；
  刪除被「還有一張進場單掛在幣安上」擋下時，清單上講的是一句不對題的話。

- **Expected Outcome:** 可驗證的結果有四項：
  1. 合約機器人的拼／改頁有「開倉容許滑價（%）」一格：新拼預填 0.1、改時顯示現值、0～5（含）、清空或超出範圍先擋下，並有一句說明後果；現貨機器人沒有這一格。
  2. 執行紀錄的下單結果多兩種狀態說法（等待成交、沒有成交），並在有進場單的那一輪多一行進場資訊：狀態、參考價、限價、成交 已成交／要求、滑價。
  3. 刪除被進場單擋下時，清單上照實說出原因與下一步，機器人留著。
  4. 設定頁不再說「將來機器人下單時」用金鑰。

- **Out of Scope:** 現貨自動下單畫面；手動撤進場單或追價；平倉、止損止盈的畫面變更；外掛說明。

---

## 2. User Personas

- **Primary Role(s):** 已登入的操作台使用者（機器人的主人）。
- **Usage Context:** 在合約機器人自己的頁面（已停止時）調整開倉容許滑價；事後展開執行紀錄對帳；在清單上刪除機器人。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 設定合約機器人的開倉容許滑價 [priority: P0]

**As a** 機器人的主人，**I want** 在合約機器人的頁面設定開倉最多接受多少滑價並看懂後果，**so that** 進場價不會被吃掉一大截、也不會因設太小而莫名不成交。

```gherkin
Scenario: 新拼一台預填 0.1（例 1）
  Given 使用者在拼一台新的合約機器人
  When 打開表單
  Then 「開倉容許滑價（%）」那一格是 0.1
  And 旁邊寫著：開倉會掛限價單、一個觸發間隔內沒成交就撤單、填 0 只在參考價成交可能常常不成交、平倉一律用市價

Scenario: 改一台時顯示它現在的值（例 2）
  Given 一台合約機器人的開倉容許滑價是 0.3
  When 使用者打開它的編輯頁
  Then 那一格是 0.3

Scenario: 0 存得下去（例 3）
  Given 合約機器人表單其餘都填好
  When 開倉容許滑價填 0 並存下
  Then 存得下去，交易服務收到的開倉容許滑價是 0

Scenario: 5 存得下去（例 4）
  Given 合約機器人表單其餘都填好
  When 開倉容許滑價填 5 並存下
  Then 存得下去，交易服務收到的開倉容許滑價是 5

Scenario: 超過 5 被擋下（例 5）
  When 開倉容許滑價填 5.01
  Then 表單顯示「開倉容許滑價必須介於 0 到 5 之間（單位：%）」，儲存鍵按不下去

Scenario: 負數被擋下（例 6）
  When 開倉容許滑價填 -0.1
  Then 表單顯示「開倉容許滑價必須介於 0 到 5 之間（單位：%）」，儲存鍵按不下去

Scenario: 清空不當成 0（例 7）
  When 使用者把開倉容許滑價那一格清空
  Then 表單顯示「開倉容許滑價必須介於 0 到 5 之間（單位：%）」，儲存鍵按不下去

Scenario: 現貨機器人沒有這一格（例 8）
  Given 使用者在拼或改一台現貨機器人
  When 打開表單並存下
  Then 表單上沒有開倉容許滑價那一格
  And 送給交易服務的內容不含開倉容許滑價，原本的值由交易服務保留

Scenario: 交易服務拒絕時照原話說（例 9）
  Given 交易服務以「進場滑價容忍度必須介於 0 到 5 之間（單位：%）」拒絕
  When 使用者存下
  Then 表單顯示交易服務那句原話，使用者留在這一頁、填的字還在
```

### US-02 — 在執行紀錄上看懂進場單怎麼收尾 [priority: P0]

**As a** 機器人的主人，**I want** 每一輪的下單結果寫出參考價、限價、成交多少與滑價，**so that** 我能對帳並判斷容許滑價設得合不合適。

```gherkin
Scenario: 全部成交（例 10）
  Given 一輪的下單結果：成交、做多、開倉 0.002 @ 84180、參考價 84154、限價 84238.1、要求 0.002、進場全部成交 0.002、滑價 0.031
  When 使用者展開執行紀錄
  Then 下單結果寫「成交 · 做多 · 開倉 0.002 @ 84180」
  And 下一行寫「全部成交 · 參考價 84154 · 限價 84238.1 · 成交 0.002／0.002 · 滑價 +0.031%」

Scenario: 還在等成交（例 11）
  Given 一輪的下單結果：等待中、進場單等待成交、已成交 0、要求 0.002、限價 84238.1、參考價 84154
  When 展開
  Then 下單結果的狀態寫「等待成交」
  And 進場行寫「等待成交 · 參考價 84154 · 限價 84238.1 · 成交 0／0.002」

Scenario: 部分成交（例 12）
  Given 一輪的下單結果：進場單部分成交 0.001、要求 0.002
  When 展開
  Then 進場行寫「部分成交，其餘已撤單」與「成交 0.001／0.002」

Scenario: 沒有成交（例 13）
  Given 一輪的下單結果：沒有成交、參考價 84154、限價 84238.1、要求 0.002、已成交 0
  When 展開
  Then 下單結果的狀態寫「沒有成交」，以提醒的語氣呈現
  And 進場行寫「沒有成交，已撤單 · 參考價 84154 · 限價 84238.1 · 成交 0／0.002」

Scenario: 成交得比參考價好（例 14）
  Given 進場滑價 -0.012
  When 展開
  Then 進場行寫「滑價 -0.012%」

Scenario: 滑價為零（例 15）
  Given 進場滑價 0
  When 展開
  Then 進場行寫「滑價 0%」，不加正負號

Scenario: 舊紀錄沒有進場資訊（例 16）
  Given 一輪的下單結果沒有任何進場資訊
  When 展開
  Then 只有原本那一句下單結果，沒有進場行

Scenario: 認不得的進場單狀態（例 17）
  Given 進場單狀態是一個認不得的說法，參考價 84154
  When 展開
  Then 進場行不寫狀態那一段，仍寫「參考價 84154」

Scenario: 註腳說明滑價正負
  Given 合約機器人的執行紀錄有內容
  When 展開
  Then 紀錄底下的註腳說明滑價以參考價為準、正值代表成交得比參考價差
```

### US-03 — 刪除被進場單擋下時知道下一步 [priority: P1]

**As a** 機器人的主人，**I want** 刪除被擋時看到原因與該做的事，**so that** 我不會以為刪除壞了。

```gherkin
Scenario: 還有進場單掛著（例 18）
  Given 交易服務以「還有一張進場單掛在幣安上」擋下刪除
  When 使用者刪除並確認
  Then 清單上顯示「這台機器人還有一張進場單掛在幣安上，請先關掉自動下單，等它撤單後再刪除」
  And 那台機器人仍在清單上

Scenario: 進場單已收尾（例 19）
  Given 這台機器人沒有掛著的進場單
  When 使用者刪除並確認
  Then 機器人從清單上消失
```

### US-04 — 說明照實情 [priority: P2]

**As a** 使用者，**I want** 設定頁照實說金鑰的用途，**so that** 我知道存了金鑰、打開自動下單就會真的下單。

```gherkin
Scenario: 設定頁的金鑰說明
  When 使用者打開設定頁的幣安交易金鑰那一段
  Then 說明寫的是合約機器人打開自動下單時會用它真的下單，不再寫「將來」
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - 開倉容許滑價：百分比，0～5（含），可有小數；清空、非數字、超出範圍一律以「開倉容許滑價必須介於 0 到 5 之間（單位：%）」擋下。檢查放在其他必填欄位之後、部位規劃之前或之後皆可，一次只說第一個擋住的理由（沿用表單慣例）。
  - 只有合約機器人有這一格並送出；現貨機器人不送，交易服務保留原值。
  - 讀不到這個設定的舊交易服務：讀作 0.1（交易服務對既有機器人的預設）。
  - 下單結果狀態：等待中且進場單在等成交時說「等待成交」；新狀態「沒有成交」用提醒語氣；其餘沿用。
  - 進場行：依序寫進場單狀態、參考價、限價、成交 已成交／要求、滑價；缺的段略過；一段都沒有就不畫。已成交缺而要求有時，已成交讀作 0。
  - 滑價：正值加「+」，零寫「0%」，負值照寫；數字照交易服務給的精度。
  - 刪除被擋：靠交易服務帶的原因分辨，不讀訊息文字。
- **Edge Cases:**
  - 數字欄位以精確小數處理，不經過浮點。
  - 交易服務改了訊息措辭：刪除被擋的分辨不受影響（看原因不看字）。

---

## 5. UI/UX Design & Interaction

- 合約機器人表單在「建議部位」那一塊之後多一塊「自動下單開倉」，只有一格與一段說明，常駐不收合。
- 進場行與下單結果同一層級、同語氣顏色，放在下單結果那一句下面。
- 刪除被擋沿用清單頂端的失敗提示。

---

## 6. Non-Functional Requirements

- 雙語：每一句新文字都有繁體中文與英文。
- 手機寬度下表單與進場行不橫向溢出（進場行自然折行）。

---

## 7. Dependencies & Risks

- 依賴交易服務 `2026-10-12-auto-order-limit-entry` 已上線。
- 風險：使用者把容許滑價設成 0 而常常不成交——說明文字明講。
