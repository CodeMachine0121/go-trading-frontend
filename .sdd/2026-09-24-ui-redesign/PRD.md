# Product Requirements Document (PRD) — 操作台全面改版

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** James Hsueh（唯一使用者兼開發者）

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 操作台長成了十二個各自為政的去處：現貨與合約各佔一格、交易策略靠拖拉積木而在手機上只能看不能改、
  助手是一枚浮在內容上的晶片。每一個能力都在，但一個畫面裡看不到「行情、正在套用的東西、下一步」三件事，
  桌面上一次看到的資訊少，手機上又有能力被拿掉。
- **Expected Outcome:**
  1. 導覽剩七個去處，現貨／合約靠一個開關在對應畫面之間移動。
  2. 每一個既有能力在新畫面上都做得到（逐項對照舊畫面，缺一不可）。
  3. 淺色、深色、跟隨系統三種外觀，全畫面一致。
  4. 交易策略在手機上也編得動。
- **Out of Scope:** 新的業務能力或規則；拖拉自訂版面、存多組版面；交易服務本身的任何改動。

---

## 2. User Personas

- **Primary Role(s):** 策略研究者兼操作者（專案作者本人）：寫策略腳本、回測、拼交易策略、派機器人、看行情、問助手。
- **Usage Context:** 桌面寬螢幕上坐下來研究（一次要看很多資料）；手機直立上隨手查看、微調、啟停機器人。

## 3. User Stories & Acceptance Criteria

### US-01 — 在現貨與合約的對應畫面之間移動 [priority: P0]
**As a** 操作者, **I want** 用一個開關在現貨與合約的同一個畫面之間切換, **so that** 我不必在導覽裡找另一邊的那一格。

```gherkin
Scenario: 從現貨行情圖表切到合約
  Given 使用者在現貨 K 線圖表
  When 使用者打開現貨／合約開關
  Then 畫面換成合約 K 線圖表
  And 開關停在「合約」

Scenario: 從合約機器人清單切回現貨
  Given 使用者在合約策略機器人清單
  When 使用者關上現貨／合約開關
  Then 畫面換成現貨策略機器人清單
  And 開關停在「現貨」

Scenario: 編輯機器人時切到另一邊，去的是清單
  Given 使用者正在編輯一台現貨機器人
  When 使用者打開現貨／合約開關
  Then 畫面換成合約策略機器人清單

Scenario: 從網址直接進入合約畫面
  Given 使用者直接打開合約 K 線瀏覽的網址
  When 畫面出現
  Then 開關已經停在「合約」

Scenario: 切過一次，其他有兩邊的畫面都帶著走
  Given 使用者在現貨 K 線圖表打開開關，到了合約 K 線圖表
  When 使用者從導覽點「策略腳本」
  Then 畫面到合約策略腳本
  And 開關停在「合約」

Scenario: 重新整理後仍記得上次那一邊
  Given 使用者上次停在合約那一邊
  When 使用者重新整理並從導覽點「策略機器人」
  Then 畫面到合約策略機器人

Scenario: 不分兩邊的畫面不改變記住的那一邊
  Given 使用者上次停在合約那一邊
  When 使用者去了交易策略畫面再點「K 線資料」
  Then 畫面到合約 K 線瀏覽

Scenario: 不分現貨合約的畫面
  Given 使用者在交易策略畫面
  When 使用者想按現貨／合約開關
  Then 開關按不動
  And 畫面說明「這個畫面不分現貨與合約」
```

### US-02 — 選擇外觀 [priority: P0]
**As a** 操作者, **I want** 選淺色、深色或跟隨系統, **so that** 白天晚上都看得舒服。

```gherkin
Scenario: 沒選過時跟隨系統
  Given 使用者從沒選過外觀
  And 系統是深色
  When 使用者打開操作台
  Then 操作台是深色

Scenario: 選過的外觀重新整理後仍在
  Given 使用者選了淺色
  When 使用者重新整理
  Then 操作台仍是淺色

Scenario: 跟隨系統時系統切換
  Given 使用者選了跟隨系統
  And 系統是深色
  When 系統切換成淺色
  Then 操作台當下換成淺色，不必重新整理

Scenario: 手動選擇不受系統影響
  Given 使用者選了深色
  When 系統切換成淺色
  Then 操作台維持深色

Scenario: 瀏覽器記不住
  Given 這台瀏覽器記不住任何東西
  When 使用者選了淺色
  Then 操作台換成淺色
  And 關掉再打開時回到跟隨系統

Scenario: 兩個入口一致
  Given 使用者在頂列選了深色
  When 使用者打開設定畫面
  Then 外觀那一項顯示「深色」
```

### US-03 — 在手機上編交易策略 [priority: P0]
**As a** 操作者, **I want** 用步驟卡編交易策略、手機上也能改, **so that** 我在外面也能調一條規則。

```gherkin
Scenario: 在步驟卡上加一條買入條件
  Given 交易策略有兩個訊號來源「突破」與「動能」
  When 使用者在「什麼算買入」那張卡上加一條「突破 等於 買入」
  Then 那張卡上出現「突破 等於 買入」

Scenario: 手機上可以編
  Given 使用者在手機直立打開一份交易策略
  When 使用者在「什麼算賣出」那張卡上刪掉一條條件
  Then 那一條條件消失，並提示有還沒存的改動

Scenario: 把兩條扣成一組
  Given 「什麼算買入」上有「突破 等於 買入」與「動能 等於 買入」兩條
  When 使用者把兩條扣成一組並選「或」
  Then 那張卡讀成「突破 等於 買入 或 動能 等於 買入」

Scenario: 刪掉之前先說有誰在用它
  Given 「什麼算買入」上有一條引用「動能」
  When 使用者打開訊號來源卡上「動能」的設定
  Then 設定裡說出「條件裡還在用「動能」，刪掉它會一併拿掉那幾句條件」

Scenario: 引用的訊號來源被刪掉
  Given 「什麼算買入」上有「突破 等於 買入」且「動能 等於 買入」
  When 使用者在訊號來源卡刪掉「動能」
  Then 「什麼算買入」只剩「突破 等於 買入」
```

### US-04 — K 線資料的查看與編輯 [priority: P1]
**As a** 操作者, **I want** 在表格旁邊直接編一根 K 線, **so that** 我不必離開正在看的那一段。

```gherkin
Scenario: 正常存好
  Given 一根 K 線的開盤 100、最高 110、最低 95、收盤 105
  When 使用者存
  Then 存好，表格上那一根換成新數字

Scenario: 最高價等於最低價
  Given 最高價 100、最低價 100
  When 使用者存
  Then 存好

Scenario: 最高價低於最低價
  Given 最高價 90、最低價 95
  When 使用者看表單
  Then 最高價那一格標紅，說出「最高價不得低於最低價」
  And 儲存按不下去

Scenario: 身分欄位改不了
  Given 使用者打開一根已存在的 K 線
  When 使用者看交易標的與起始時間
  Then 兩格都是唯讀，並說明要改請刪掉重建
```

### US-05 — 其餘畫面照新設計、能力不少 [priority: P0]
**As a** 操作者, **I want** 每個畫面換新樣子後舊能力都還在, **so that** 改版不讓我失去任何東西。

```gherkin
Scenario: 行情圖表的即時跟盤照舊
  Given 使用者在現貨 K 線圖表看一檔有即時更新的交易標的
  When 市場跳動
  Then 圖上最後一根跟著動，行情摘要的價格同步更新

Scenario: 合約行情摘要多了標記價格
  Given 使用者在合約 K 線圖表
  When 畫面出現
  Then 行情摘要看得到標記價格、指數價格與溢價指數
  And 沒有記錄的那一條畫成「—」而不是零

Scenario: 回測結果出現在編輯器下方
  Given 使用者在策略腳本畫面寫好一支「一個信號」種類的算式
  When 使用者按執行回測
  Then 成績單、資金曲線與交易明細出現在編輯器下方，畫面不換頁

Scenario: 需要處理的那一輪說出原因
  Given 一台機器人最近一輪買入與賣出同時成立（規則打架）
  When 使用者看它的執行紀錄
  Then 那一輪標成需要處理，並附上建議的下一步

Scenario: 手機上叫出助手
  Given 使用者在手機直立
  When 使用者按底部的「助手」
  Then 助手以整頁出現，接著的是同一段對話

Scenario: 連不上後端
  Given 交易服務沒有回應
  When 使用者打開任何一個畫面
  Then 畫面明說連不上，而不是一片空白
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - **對應畫面**：現貨 K 線圖表 ⇄ 合約 K 線圖表、現貨 K 線瀏覽 ⇄ 合約 K 線瀏覽、現貨策略腳本 ⇄ 合約策略腳本、
    現貨策略機器人（清單、建立、編輯）⇄ 合約策略機器人清單（編輯或建立中切過去一律到清單）。其餘去處沒有對應畫面。
  - **外觀**：淺色／深色／跟隨系統，預設跟隨系統；記住在這台瀏覽器；記不住時本次仍生效。
  - **導覽**：寬螢幕側欄七個去處（行情圖表、K 線資料、策略腳本、交易策略、策略機器人、Marketplace、設定），有兩邊的那幾格指向使用者最後停留的那一邊（沒停過時是現貨）；
    窄螢幕底部五格（行情、策略、機器人、助手、更多）。
  - **交易策略步驟卡**：訊號來源 → 什麼算買入 → 什麼算賣出；條件群組、且／或、一組的規則全部沿用既有規則，
    只是改用「挑」而不是「拖」。窄螢幕不再是唯讀。
  - 其餘一切業務規則（送出前的把關、拒絕的說法、空清單、未儲存確認、時區）一字不變。
- **Edge Cases:**
  - 有未儲存的改動時按開關或換畫面 → 照既有的未儲存確認攔下。
  - 交易服務沒有回應 → 每個畫面都明說連不上。
  - 瀏覽器記不住外觀 → 跟隨系統，選了本次生效。

## 5. UI/UX Design & Interaction

- **Prototype Link:** `design/web.html`（寬螢幕，可切換畫面、現貨／合約、外觀）、`design/mobile.html`（手機直立十二個畫面）。
- **Key Interactions:**
  - 頂列：現貨／合約開關、顯示時區、外觀快速切換、助手鍵。
  - 側欄底部常駐後端連線燈與目前登入的帳號。
  - 手機上的次要表單（K 線編輯、步驟卡設定、回測結果）從下方拉出。
  - 空清單、載入中、連不上後端三種狀態每個畫面都有明確樣子。
- **視覺語言：** 深色預設為交易終端風格；上漲綠、下跌紅；所有價量數字等寬對齊。

## 6. Non-Functional Requirements

- **Performance:** 切換外觀與現貨／合約開關不重新載入整個操作台。
- **Security:** 沿用既有登入與開通把關，不新增。
- **Compatibility:** 最窄手機直立寬度；手機橫放可用高度約同寬仍成立；近兩年的主流瀏覽器。
- **Analytics / Tracking:** N/A

---

## 7. Dependencies & Risks

- **External Dependencies:** 交易服務（不改動）。
- **Known Risks:** 舊畫面裡有大量細緻的互動規則（圖表重新取的時機、即時跟盤、未儲存確認），改版時容易漏；
  須逐一對照舊畫面的行為清單，並保留有互動邏輯的元件測試。
