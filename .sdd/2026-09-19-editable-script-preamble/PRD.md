## 1. Background & Goal

- **Problem Statement:** 算式編輯器把一份指標算式切成兩塊：最上面的宣告與匯入唯讀、由畫面備妥，使用者只寫它下面那一段。
  於是使用者**看到的不是他送出去的那一份**——畫面在背後把兩塊接起來才送出，載入時又要把它拆開；
  拆不出來時還要跳一句「這一支認不出開頭」的提示，而那句話對使用者毫無意義，他從沒要求把算式切成兩塊。
  想多匯入一樣東西、或自己決定開頭怎麼寫，也一律做不到。
- **Expected Outcome:** 編輯區就是一整份算式，從第一行到最後一行都是使用者的。
  開頭那幾行改為**預填**——開一份新的空白策略腳本時像進入點一樣自動補上，補上之後照樣改得動。
  載入既有策略腳本時原文照搬，送出與儲存時原文照送，畫面不再替使用者接合或拆解任何東西。
- **Success Metrics:**
  1. 使用者在編輯區看到的那一份，與送出去執行、存下去的那一份**逐字相同**。
  2. 開一份新的空白策略腳本後不必自己打任何一行就能送出計算。
  3. 「認不出開頭」這類提示從畫面上完全消失。
- **Out of Scope:** 前端做語法檢查或匯入白名單提示；已存策略腳本的任何遷移；
  可用的匯入範圍（由執行沙箱決定）；執行算式那一方的任何改動。

---

## 2. User Personas

- **Primary Role:** 策略腳本研究者（專案作者本人）。
- **Usage Context:** 指標計算畫面的算式編輯器。寫算式、預覽、調、回測，一輪很多次；桌面與手機都用。

## 3. User Stories & Acceptance Criteria

### US-01 — 編輯區就是一整份算式 [priority: P0]

**As a** 策略腳本研究者, **I want** 眼前那一整份算式從第一行起都改得動,
**so that** 我送出去的就是我看到的那一份，想改開頭也改得了。

```gherkin
Scenario: 沒有任何唯讀區塊
  Given 畫面上是一份預填好的新空白策略腳本
  When 使用者看編輯器
  Then 開頭的宣告與匯入就在編輯區裡，且改得動
  And 畫面上沒有任何唯讀的算式區塊

Scenario: 行號從第一行算起
  Given 編輯區的第一行是開頭的宣告
  When 使用者看行號
  Then 那一行標示為第 1 行

Scenario: 送出的就是眼前那一份
  Given 使用者把一個用不到的匯入刪掉
  When 使用者送出計算
  Then 送去執行的算式就是他眼前那一份，少了那個匯入

Scenario: 存下的就是眼前那一份
  Given 使用者在進入點旁邊多寫了一個輔助函式
  When 使用者儲存
  Then 存下來的是他眼前那一整份，含那個輔助函式
```

### US-02 — 新的空白策略腳本自動補上開頭與進入點 [priority: P0]

**As a** 策略腳本研究者, **I want** 開一份新的空白策略腳本時開頭與進入點都已經備妥,
**so that** 我不必每次自己把宣告、匯入與簽章打出來。

```gherkin
Scenario: 信號種類的空白算式
  Given 指標值種類是「一個信號」
  When 使用者開一份新的空白策略腳本
  Then 編輯區是開頭的宣告與匯入，接著一個回傳信號的空進入點

Scenario: 一串數字種類的空白算式
  Given 指標值種類是「一串數字」
  When 使用者第一次進入畫面
  Then 編輯區是開頭的宣告與匯入，接著一個回傳「名稱對應一串數字」的空進入點

Scenario: 未改動的預填內容不算未儲存的變更
  Given 還沒載入過任何策略腳本
  And 編輯區還是那份未改動的預填內容
  When 使用者按「新的空白策略腳本」
  Then 不出現「放棄尚未儲存的變更？」的確認

Scenario: 清成空白也不算未儲存的變更
  Given 還沒載入過任何策略腳本
  And 編輯區被清成完全空白
  When 使用者按「新的空白策略腳本」
  Then 不出現「放棄尚未儲存的變更？」的確認

Scenario: 改過開頭就算使用者寫的東西
  Given 還沒載入過任何策略腳本
  And 使用者把預填內容開頭的一個匯入刪掉了
  When 使用者按「新的空白策略腳本」
  Then 先出現「放棄尚未儲存的變更？」的確認
```

### US-03 — 範例內容是一整份可直接執行的算式 [priority: P0]

**As a** 策略腳本研究者, **I want** 填入的範例本身就跑得起來,
**so that** 我可以按一下就送出，看看這一種指標值種類算出來長什麼樣。

```gherkin
Scenario: 範例含開頭與整個進入點
  Given 指標值種類是「一個數字」
  When 使用者按「填入範例」
  Then 編輯區是一整份算式：開頭的宣告與匯入，接著整個進入點函式

Scenario: 填入範例後直接送得出去
  Given 使用者剛填入範例
  When 使用者送出計算
  Then 算得出結果，使用者不必自己補任何一行
```

### US-04 — 載入既有策略腳本原文照搬 [priority: P0]

**As a** 策略腳本研究者, **I want** 載入一支策略腳本時看到的就是它存著的那一整份,
**so that** 我改得到它的每一行，也不會收到任何我看不懂的提示。

```gherkin
Scenario: 載入一支策略腳本
  Given 一支策略腳本存著一整份算式
  When 使用者載入它
  Then 編輯區是那一整份，一字不差

Scenario: 開頭寫得與預填不一樣也照樣原文帶入
  Given 一支策略腳本的開頭多匯入了一樣東西
  When 使用者載入它
  Then 編輯區照樣是那一整份原文
  And 畫面不出現任何關於開頭的提示

Scenario: 載入後原封不動再存一次，內容不變
  Given 使用者載入一支策略腳本後一個字都沒改
  When 使用者再存一次
  Then 存下來的內容與載入時逐字相同
  And 開頭那幾行只出現一次
```

### US-05 — 改指標值種類只動進入點那一行 [priority: P1]

**As a** 策略腳本研究者, **I want** 改種類時只有進入點的回傳型別跟著換,
**so that** 我不必自己回去改簽章，也不必擔心別的地方被動到。

```gherkin
Scenario: 換掉第一個進入點的回傳型別
  Given 編輯區的進入點回傳「名稱對應一個數字」
  When 使用者把指標值種類改成「一個信號」
  Then 進入點那一行改為回傳信號
  And 開頭那幾行與函式內容一字不動

Scenario: 認不出進入點時整份不動
  Given 編輯區裡沒有一行認得出是進入點
  When 使用者改指標值種類
  Then 編輯區一字不動
```

### US-06 — 寫壞了由執行那一方說 [priority: P1]

**As a** 策略腳本研究者, **I want** 畫面不要替我判斷算式寫得對不對,
**so that** 我不會被一個猜出來的規則擋住，而真正跑不動的理由由跑它的那一方說清楚。

```gherkin
Scenario: 開頭被刪掉照樣送得出去
  Given 使用者把開頭的宣告刪掉了
  When 使用者送出計算
  Then 畫面照樣把那一份送去執行
  And 由執行結果回報那一份跑不起來

Scenario: 整份空白當場擋下
  Given 編輯區被清成完全空白
  When 使用者送出計算
  Then 畫面當場在算式那一格說「請填寫算式內容」
  And 不送出任何計算
```

## 4. Business Flow

### Happy Path

1. 使用者進入指標計算畫面 → 編輯區已是一份預填好的算式（開頭 ＋ 空進入點），游標可落在任何一行。
2. 使用者寫算式（想改開頭就改）→ 送出計算 → 送去執行的就是眼前那一份。
3. 使用者儲存 → 存下來的就是眼前那一份。
4. 下次載入它 → 編輯區又是那一份，一字不差。

### Edge Cases

| 情境 | 行為 |
| :--- | :--- |
| 編輯區整份空白時送出 | 就地說「請填寫算式內容」，不送出 |
| 編輯區整份空白時儲存 | 由畫面擋下、不送出，說的是與送出計算**同一句話** |
| 開頭被刪或寫壞 | 照樣送出，由執行結果回報失敗 |
| 載入的策略腳本開頭與預填不同 | 原文帶入，不提示 |
| 未改動的預填內容 / 完全空白 | 不算未儲存的變更 |
| 認不出進入點那一行時改種類 | 整份不動 |

## 5. UI/UX Requirements

- 編輯器裡**只剩一塊**可編輯的程式碼區，上方的唯讀區塊拿掉。
- 行號從 1 開始，與執行回報的行號對得上。
- 編輯器上的說明文字不再說「在匯入底下寫」，改成說明這是一整份算式、至少要有一個進入點、換指標值種類會改它的回傳型別。
- 「載入的這一支認不出開頭」這類通知從畫面上移除。
- 空／載入中／錯誤狀態與現況相同：錯誤訊息就地標在算式那一格下方。

---

## 6. Non-Functional Requirements

- 不新增任何對外請求；本切片完全在畫面與領域規則之內。
- 編輯區在手機直立（寬 390）上照舊可讀可用——少了一塊唯讀區之後，可寫的高度只會變多。

---

## 7. Dependencies & Risks

- **Dependencies:** 無。執行算式的那一方收到的一直都是一整份算式，本切片不改變它。
- **Risks:**
  - 既有策略腳本存的開頭若與預填的不同，載入後使用者會第一次看見它——這正是預期行為，不是缺陷。
  - 使用者從此可能存下跑不起來的算式。這與現況一致（算式本來就可以存成半成品），失敗訊息仍由執行那一方給。
